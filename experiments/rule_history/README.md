# 局部 rule history 消融

已在本仓库的 egglog 内核上运行一轮受控实验。结论是：**历史能补足较弱结构特征遗漏的信息，但这批数据没有证明规则身份在保留共享关系的结构特征之外还提供独立收益。**

## 实验对象

16 种手写算术表达式，6 种规则调度，4 次独立重命名运行，每次取 4 个执行轮次，共 1,536 个快照、22 种局部模板。实际执行了交换、结合、分配、恒等和显式无效规则。每一步都对照无 trace 执行，比较整个序列化数据库及 `updated`；每个模板都带原 child 绑定还原，逐节点验证。

主指标为 top-1 候选与查询是否具有相同的局部模板：允许外部端口统一重命名，保留端口类型、跨节点共享和 SELF 自引用。这是局部结构检索，**不是整个子图同构或语义等价判断**。近似指标另见完整报告，其端口对齐并非全局最优近似匹配。

## 关键结果

下表为 5 个配对候选排序种子的平均精确模板命中率；它们只衡量并列候选的敏感性，不是独立数据集置信区间。

| 配置 | 独立重命名 | 未见调度 | 未见初始表达式 |
|---|---:|---:|---:|
| 结构：逐节点形状＋child operator 集合 | 97.6% | 98.8% | 55.0% |
| 上述结构＋规则集合 | 100.0% | 100.0% | 77.9% |
| 上述结构＋绑定关系，移除规则身份 | 100.0% | 100.0% | 78.3% |
| 上述结构＋规则身份与绑定关系 | 100.0% | 100.0% | 78.3% |
| 上述结构＋打乱历史，同真实历史权重 | 96.1% | 96.6% | 54.0% |
| **结构＋端口共享位置统计，无 trace** | **100.0%** | **100.0%** | **83.3%** |
| 端口共享结构＋规则历史 | 100.0% | 100.0% | 83.3% |
| 字典中正确模板存在率（上限） | 100.0% | 100.0% | 83.3% |

所有组合权重都只在验证集选择；打乱历史的固定权重对照复用真实历史选出的权重。候选字典在同一划分的各个消融中相同。更完整的 16 个配置结果在 `../../results/rule_history/report.md` 和 `metrics.csv`。

一个重要反例：24 种规则集合中，9 种对应不止一种局部模板。因此“规则历史一致”本身不是确认结构相同的依据。

去掉当前轮次，只使用更早的局部事件，较强结构基线的三个测试命中率为 98.6%、99.4%、69.2%，低于包含当前轮次的历史。这里旧绑定仍按当前快照 canonicalize，不是未来状态预测实验。

本次所选时间特征配置在未见调度上仅为 71.3%，低于结构基线的 98.8%。需要把规则的局部作用与调度造成的出现轮次分开。去掉显式 noop 后，在未见表达式上为 76.7%，也没有优于原有的规则＋绑定特征；这只针对人为设置的 noop，未对所有实际提交进行归因。

## 应当如何使用历史

当前证据支持将局部历史用于：

1. 在只保存弱结构摘要时，为模板候选排序。
2. 用已有绑定为模板实例提供端口对齐的起点。
3. 为增量系统标记需要重新检查的局部区域。

最后的确认仍需检查节点、绑定和精确 residual。对第三点，这次未测增量维护速度。

不能据此声称规则历史对真实大型 e-graph 没有增益：这个语料只有 22 种局部模板，补充共享关系后的结构基线已经达到字典覆盖上限，无法进一步区分更强的方法。未见表达式测试只有两个初始形状；重命名测试是有意设置的简单重复对照。

## 实现边界

- `Survived` 是执行通道保留，不是 committed mutation。规则历史来自真实内核 trace。
- 编译器可能消除用户 `root` 别名。采集器通过本实验已知规则的 LHS 和保留的 `x/y/z` 重建归属；没有依赖生成变量名，也没有实现适用于任意规则的通用 provenance。
- 历史 root 随 merge 重新 canonicalize；不会把全局 event ID 当作因果顺序。
- 离线标签用最多 6 个外部端口的穷举重命名。它是验证 oracle，不是建议上线的候选检索算法。
- 当前 residual 指标是节点数；没有测真实压缩字节、Zobrist 解码率或运行时加速，不能把检索增益换算为压缩收益。
- 字典包含重复观察，top-4 是四条观察，不是四种不同模板。后续大型实验应增加模板去重、更多独立程序与完整成本测量。

## 复现

在仓库根目录执行：

```sh
cargo run --bin rule_history_data -- results/rule_history/data.jsonl
python3 experiments/rule_history/ablate.py
python3 -m unittest discover -s experiments/rule_history -p 'test_*.py'
cargo fmt --package egg_layout -- --check
```

Python 分析仅依赖标准库。原始数据、完整指标、数据摘要和详细方法均保存在 `results/rule_history/`。无 trace 对照与 round-trip 验证在采集及分析时自动执行；另有 6 项测试覆盖共享关系、自引用、类型、端口重命名、历史消融和运行级数据隔离。
