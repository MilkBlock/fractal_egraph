# 分段重复与短段交替：依赖历史对照

本轮直接比较组合形状，而非比较同一 R23 链能走多深。
数据是 math_microbenchmark 原始调度的前 6 轮原生 committed row-provenance 历史。
每条路径的相邻执行必须有真实 producer→consumer 行依赖；多条 read 支撑同一执行对
只算一条事件路径，并保留其连接信息。来自不同 scope 的事件不连接。

## 对照定义

四个执行事件：AABB/BBAA 对 ABAB/BABA；六个事件：AAABBB/BBBAAA 对 ABABAB/BABABA。
同长度、同一对规则、相同每规则次数。AAAA 单列为纯重复对照，不能冒充同多重集比较。

这里 A/B 是基础规则，作为候选族“一步”的代理，不是已经认证的 fractal macro。
未自动识别 trigger 注入段或 until-turning-point 边界，所以这是一阶组合组织规律验证。
路径有外部 producer 时显式统计，但未把其余 DAG 全部纳入模板；这些不是可直接执行的闭合快捷规则。
union-only 的 producer 不在此路径图中，rebuild 支撑保留 kind；因此覆盖范围有 trace 边界。

模板同时保留规则名、读写 AST 连接位置及跨执行的 binding value 别名关系。
使用原始历史 Value 别名，不声称已跨 union 版本统一所有等价 binding。具体数据 ID 不进入模板，
但相等/不等模式保留。另做只看规则名的消融，检验丢弃 binding 后会夸大多少复用。

## 结果

四步路径：

| 组织 | 1–4 轮训练路径 | 5–6 轮新根路径 | 合计 | 留出根去重数 | 留出 productive 根 |
|---|---:|---:|---:|---:|---:|
| 分段重复 | 2 | 74 | 76 | 66 | 18 |
| 短段交替 | 15 | 330 | 345 | 234 | 160 |
| 纯重复 | 1 | 73 | 74 | 69 | 51 |

productive 指该根有实际直接 Inserted 写入或改变等价关系的 union；不是单纯 logical match。
每个根可能支持多条路径，表中单独给出去重数。类别间仍可能共享根，不能相加作为总执行次数。

不能仅据合计 345/76 宣称交替普遍更好。控制规则对后：

| 规则对 | 分段重复（全部） | 短段交替（全部） |
|---|---:|---:|
| R0/R2：Add 交换/结合 | 18 | 288 |
| R1/R3：Mul 交换/结合 | 3 | 39 |
| R1/R23：Mul 交换/分部积分 | 16 | 13 |

优势主要来自交换/结合，不是 R23 的普遍现象。
六步分段/交替分别为 5/34，但训练前四轮两组都没有六步路径，不能评估学到的六步库的留出复用。

## 冻结库的后续复用消融

按训练频率排序，每组最多 8 个模板，测试时不重新挑选。

| 四步组织 | 实际选中模板 | 保留 binding/位置的留出命中 | 只看规则名的留出命中 |
|---|---:|---:|---:|
| 分段重复 | 2 | 0/74 | 14/74 |
| 短段交替 | 8 | 41/330 | 214/330 |
| 纯重复 | 1 | 0/73 | 27/73 |

41 条交替命中涉及 33 个不同根、41 组具体 binding、69 个去重历史事件和 44 个 producer
write ID。这是历史连接覆盖，不是 tier-0 e-node 覆盖或实际压缩率。

实际入选库数量不相同，因此另给同规则对、相同实际 K 的比较。
只有 R1/R23 在训练两组都有模板，共同 K=2；分段/交替留出命中都是 0。
其他规则对一组无训练候选，共同 K=0，属于无比较能力，不解释成双方同样差。

## 留出和因果边界

严格要求整条路径所有事件均在第 5–6 轮时，没有四/六步样本。
上述评估按根事件轮次划分：新根可复用更早祖先，训练和测试根不重合，但祖先重合。
这是后续执行延续预测，不是独立运行泛化；不报告显著性检验。

事件 ID 相邻的四元组对照有 1,369 个纯重复、42 个分段重复、115 个其他，
其中没有任何四元组的三条相邻边全部得到依赖证实。事件 ID 顺序也不等于并行执行的
因果总序。负对照说明不能从时间/记录相邻推导这里的组合规律。

结果支持“某些规则对的交替结构更常见，并可跨具体 binding 重用”，尚未证明：
1. 优势由 egglog 调度机制导致，而不是这些规则的代数/生成关系导致；
2. 一般 fractal 族都应采用交替策略；
3. 交替结构有更好的 babble 净压缩或实际 tier-0 替换收益。
这些需要多工作负载、调度干预，以及完整 DAG 的库学习成本对照。

## 复现

```
python3 experiments/comb_alternation/run.py
python3 -m unittest discover -s experiments/comb_alternation -p test_analyze.py
cargo test --bin combine_profile
```

结果 JSON 保留各规则对、训练模板、事件路径实例、只看规则名的消融、历史覆盖计数。
原生 profile 在临时目录生成，不提交体积更大的完整原始历史。

实现检查：新增轮次标记后，前 5 轮依赖根仍为 582，与已有 profile 一致。
依赖 tracing 会串行化相关 action/commit 以获得明确 producer；它记录的是选中的来源，
不是所有可能的证明。因此这些频率还可能受 provenance 选择影响，不能直接推广为默认并行调度的偏好。
本用例保留的命名规则变量均为 Math；该别名编码尚未提供通用跨 sort 值规范化。
