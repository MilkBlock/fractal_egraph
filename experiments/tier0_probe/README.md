# Tier-0 LHS / RHS 覆盖探针

在 `math_microbenchmark/combined.egg` 的原始 11 轮 schedule 跑完后测量。
原图包含 **1,047,896 个 Math 构造器 e-node**；不是前 5 轮的历史窗口。

选择三个模式作为首轮实例：R15（乘积求导）、R23（分部积分）、
combined_017（R23 的 producer–consumer 自组合，对应之前的双连接模板）。
combined_017 是导出的 witness bundle，探针不执行它作为 shortcut。

## 原生探针如何工作

每个 LHS/RHS 在最终图的独立 clone 中创建 `__ProbeInstance` 类型及标记
构造器。原始构造器调用展开为原生 LHS 查询，标记捕获所有匹配变量和
显式节点结果值。只运行独立 probe ruleset 一次，不再运行原始规则。
标记没有 union 进 Math。六个探针结束后逐行检查原始表，确认没有变化。

节点身份是冻结图中的 `(table, canonical inputs, output class)` 行，
不是单独的 e-class ID。一个 e-class 的不同 e-node 分开统计。变量所代表
的整个子图不计入覆盖；同一匹配中的重复构造器节点也只计一次。

RHS 探针将 union 两端作为已经成立的等式形状匹配，不重新执行 union。
组合 RHS 额外保留 annotation 指定的 binding 连接约束；这些辅助约束的
节点不计入 RHS 覆盖。测试确认去掉连接约束会把 2 个相关实例错误地变成
4 个笛卡尔积实例。这里计数结构实例，不推断对应规则历史上执行过几次。

## 实测覆盖

| 模式 | 侧 | 标记实例数 | 实例数×语法节点数 | 去重覆盖节点 | 去重覆盖率 |
|---|---|---:|---:|---:|---:|
| R15 | LHS | 25,364 | 50,728 | 32,067 | 3.06% |
| R15 | RHS | 4,359 | 21,795 | 10,721 | 1.02% |
| R23 | LHS | 69,273 | 138,546 | 92,823 | 8.86% |
| R23 | RHS | 12,548 | 87,836 | 54,458 | 5.20% |
| combined_017 | LHS | 12,585 | 125,850 | 41,697 | 3.98% |
| combined_017 | RHS | 3,283 | 45,962 | 24,464 | 2.33% |

LHS 合计去重覆盖 109,403 个节点（10.44%），RHS 合计 64,239 个（6.13%）。
两侧共同去重后为 **137,954 个（13.16%）**，不能把两侧比例直接相加。

R23 RHS 是很直观的算重例子：

```
Sub(Mul(a, Integral(b,x)),
    Integral(Mul(Diff(x,a), Integral(b,x)), x))
```

`Integral(b,x)` 在语法中出现两次。同一实例内部合计扣掉 12,548 次重复：
87,836 → 75,288；跨实例再扣掉 20,830 次：75,288 → 54,458。

## 节点数压缩估计

提供两个明确不同的 packing 模型：

1. **整片 footprint 互斥**：实例之间不能共享任何覆盖节点，假设整片可以
   由一个新实例节点代替。它忽略外部访问要求，不是安全删除证书。
2. **接口与外部引用保留**：保留模式根、变量接口、辅助条件引用的类，
   以及存在外部 child 引用或外部 e-class 成员的节点。仅将剩余节点作为
   interior；选择时禁止重复移除，以及移除另一个已选实例保留的接口。
   保留的边界可以共享。

两者选集不同，第二种可以选择更多共享边界的实例，因此其结果不必小于
第一种。两者都是 greedy，不是最优值或互相嵌套的上下界。

| 模式 | 侧 | 整片互斥净节点估计 | 接口保留净节点估计 |
|---|---|---:|---:|
| R15 | LHS | 6,700 | 0 |
| R15 | RHS | 246 | 792 |
| R23 | LHS | 23,547 | 0 |
| R23 | RHS | 2,792 | 12,923 |
| combined_017 | LHS | 2,164 | 0 |
| combined_017 | RHS | 1,965 | 3,662 |

每个已选实例收取一个新节点，每个被使用的模式收取 `k+1` 个共享模板
节点（k 为其构造器出现次数）。净值小于零时允许直接不压缩。
这些是节点单位假设，尚未计算参数、索引和约束的字节成本。

将六个候选族共同选择后：

- 整片互斥模型净估计 **31,780 个节点（3.03%）**。
- 接口保留模型净估计 **13,700 个节点（1.31%）**：20,701 个 interior，
  减去 6,972 个实例节点，再减去 29 个模板节点。

接口保留模型的 LHS 为零不说明 LHS 无法压缩，只表示这里较严格的边界
保留规则没有得到正收益实例。真正实现压缩仍需要虚拟节点匹配、原类
接口及 rebuild 支持。本次没有删除任何原节点，也没有测量实际压缩后 RSS。

## 复现与审计

```
python3 experiments/tier0_probe/run.py
CARGO_INCREMENTAL=0 cargo test --bin tier0_probe
```

- `results.json`：所有计数、生成的 probe 程序、分侧及联合估计。
- `results.json.coverage.jsonl`：每个实例对应的节点 ID 与 interior。
- `results.json.nodes.jsonl`：这些节点的原始 table/key/output。

较大的 JSONL 复现时生成，不提交。脚本从 JSONL 独立复算实例数、覆盖量
和联合覆盖，并核对节点字典；本轮验证全部通过。

工具接受指定规则名，可按同样方式扩展模式集合。目前只接受正向构造器
和等式形状；不支持的动作或 primitive 显式报错。只有变量的 RHS 没有
显式结构，标为未执行实例枚举，覆盖为零，不能把它误报成零个匹配。
