# Dynamic resident matrix contexts

**Fixed-width computation, growing instance count.** Each premise-count bank
contains dense context records `(generation, target, premise slots...)`.
Its certified ridge separator and matrix wiring format stay fixed; new structures
append records and fact coordinates. GPU truth survives buffer growth. This is
the next version of the standalone closure executor, not the full egglog backend.

## Update and expiration contract

The caller supplies a committed batch of typed structural row upserts/removals,
authoritative aliases, and optional explicit predicate assertions/subsumptions:

```
committed external changes
  -> CPU: locate affected row owners through reverse subscriptions
  -> CPU: compile changed bindings, deduplicate supported clauses
  -> binary delta: new coordinates, aliases, changed context records
  -> GPU: update resident buffers
  -> next Run: gather -> GEMM -> threshold -> publish -> next Run
```

CPU retains wiring and identity metadata, not evolving predicate truth. A union
also revisits subscribed anchors that previously failed a repeated-variable
constraint: `Pair(a,b)` can enable the `Pair(x,x)` clause after `union(a,b)`.
Two sources supporting the same clause share one context. Removing one source
does not remove the other source's guarantee.

Expiration is exact, without TTL, sampling or a candidate cap:

- Row replacement/removal or subsumption withdraws that source's clauses.
- A last-supported clause is immediately swap-removed from its dense bank.
  Moved/reused slots receive a new generation. Cleared tails cannot be executed.
- Empty banks release their owned buffers. Nonempty banks use geometric growth
  and shrink when quarter-full; allocator headroom is not an executable context.
- GPU publication checks interface epoch, slot generation and Run number.
  Stale commands/patches are rejected before state mutation. A GPU command failure
  poisons the worker instead of allowing execution on partially updated state.
- An unrelated update leaves this interface's epoch unchanged.

“Immediately” means **when the event batch is applied, before the next Run**.
In-flight Runs retain their snapshot; we do not mutate their inputs mid-dispatch.
Use finite `step` calls to interleave changes. A `saturate` request completes
before the worker processes its next command.

A temporarily false prerequisite is not an expired context: it may become true
in a later Run. Previously derived facts also survive context retirement, as in
native egglog. An explicit subsume hides a predicate separately. Hidden wins
when predicate keys merge, and asserting the same constructor does not unhide it.
Fact/alias coordinates are retained as state identities; this change reclaims
contexts, not every historical fact coordinate.

## Scope

The admitted class still has one structural anchor per rule and unary existence
premises/outputs, with keys bound by that anchor and unobservable predicate result
identities. The anchor is immutable during a Run, but can be a function row whose
value changes between Runs. External union, append, replacement and subsumption
are supported. Closure truth and iteration remain on GPU; structural growth is
supplied by external events rather than generated by this closure's RHS.

Container-valued anchors, arbitrary primitive guards, multiple-anchor joins,
observable predicate result identities and predicate deletion/revival are outside
this contract. The dynamic compiler rejects container anchors. This is not
automatic support for every `.egg` rule.

`SnapshotEvents` is a **validation-only** event producer. It differences native
structural snapshots and ignores predicate truth after bootstrap. A production
commit/rebuild journal adapter and incremental publication into the main engine's
tables remain unconnected. Do not count snapshot differencing as an optimized
runtime, or claim the complete Pass 3 runs on this executor.

The final comparison reconstructs GPU predicates once over the authoritative
external carrier. It checks rows, values, equality and visibility; native rule
execution never repairs GPU answers. Every selected Run's visible predicates and
update flag are checked independently. Final external updates do not trigger an
extra closure Run. The schedule follows native control flow, not an old GPU
replay's iteration count.

Final context-owned buffers: **1,782,272 bytes** for 32,180 live records and
52,480 reserved slots. Metal's final total allocation is 2,883,584 bytes for this
worker, not RSS or full egraph memory. Total binary uploads are 1,001,472 bytes.
Diagnostic snapshots download 250,068,632 bytes; normal Run responses only return
small status messages.

This is correctness evidence, **not an end-to-end speedup**. The snapshot event
adapter scanned 11,751,307 rows and took 85.816 s; changed-wiring compilation took
0.640 s. The expensive adapter must be replaced by real commit/rebuild events
before timing production integration. The previous frozen-context timings do not
measure this dynamic validation path.

A subsequent [dynamic performance comparison](PERFORMANCE.md) measures the same
real updates without per-Run verification traffic, including CPU wiring costs.

## Build and reproduce

Use Python with NumPy and the existing shared Cargo target for a quick rebuild.
Outputs must be fresh directories. Build products and native snapshots stay in
`out/`; only source and compact results are tracked.

```sh
python3 experiments/matrix_closure/build.py --output out/matrix-dynamic-build-all --target TARGET

MTL_DEBUG_LAYER=1 python-with-numpy experiments/matrix_closure/verify_dynamic.py \
  --frontend out/matrix-dynamic-build-all/oracle/frontend \
  --worker out/matrix-dynamic-build-all/dynamic-worker --output out/dynamic-fixture

MTL_DEBUG_LAYER=1 python-with-numpy experiments/matrix_closure/verify_dynamic_raytrace.py \
  --source PASS3.egg --frontend out/matrix-dynamic-build-all/oracle/frontend \
  --worker out/matrix-dynamic-build-all/dynamic-worker --output out/dynamic-raytrace

MTL_DEBUG_LAYER=1 python-with-numpy experiments/matrix_closure/replay_dynamic.py \
  --reference out/dynamic-fixture --worker out/matrix-dynamic-build-all/dynamic-worker \
  --output out/dynamic-direct --mode direct

python-with-numpy -m unittest discover -s experiments/matrix_closure -p 'test_*.py'
```

`DynamicContext.apply` is the event-facing API; `Resident.apply/step/saturate`
drive the persistent worker. Numeric requests use binary frames; compact JSON
replies carry status only, and snapshot payloads are binary. The worker's optional
snapshot operation is for audit/export, not a dependency of GPU iteration.
The client does not retain command history by default. The small differential
fixture explicitly enables it to produce a replayable verification transcript.
