# 共享端口索引、桶标脏和预算回退

这个实验实际尝试了前一轮提出的低成本支持方案。结论是：可以保证局部
补查和正确回退，但重扫整个脏桶会重复处理旧配对，不能因此声称优于
已有的增量 e-matching。

## 实现与隔离

- 公共 Cache 保存 `(e-class, k)` 下的两侧事实集合，以及
  `e-class -> k 集合` 反向端口索引。
- 用真实 egglog `UnionEvent` 的 lhs/rhs/canonical 更新共享桶。
  只遍历被合并一侧的端口，不扫描所有规则或所有事实。
- 脏集合按桶去重；flush 前再 canonicalize，合并多次 union 的通知。
- 缓存路径直接枚举脏桶 P×Q，将结果写入一个独立的 optimized EGraph。
  它在初始化后不运行全局 consume，避免基线替候选实现补漏。
- 超过每桶 pair 预算时，写入临时 `Pending(k,c)` 关系，由一个预先编译的
  原生规则执行 `Pending ⋈ P ⋈ Q -> Out`。所有请求批量运行一次，然后
  删除 Pending；不积累临时规则，也不复制原生结果做事后回填。
- 另一份 ordinary EGraph 按正常 consume 调度执行作为对照。每阶段使用
  不可变初始事实与原生 canonicalization 独立构造期望值，核对缓存、
  optimized、ordinary 的所有元组及数量。

这仍是仓库外层的调度/缓存原型，并未接入 egglog 内核调度器。回退是真实
原生匹配，但缓存和通知路由是实验代码。只验证一条二元连接规则，没有
实现多规则订阅、guard、删除、pop 或缓存内容驱逐。

## 场景与结果

16 个 Group、16 个 k，每 group 只涉及 4 个 k；每个桶初始有 2×2 配对。
共 256 条 P/Q 事实、64 个桶、256 个初始 Out。

| 阶段 | 脏信号 | 合并后脏桶 | 本地整桶检查 | 普通 consumer 诊断候选 | 新 Out |
|---|---:|---:|---:|---:|---:|
| 两次关联 union，之后统一 flush | 8 | 4 | 144 | 128 | 96 |
| 合并没有相同 k 的两个 group | 4 | 4 | 16 | 16 | 0 |
| 重复 union | 0 | 0 | 0 | 0 | 0 |
| union 后新增一个 P | 1 | 1 | 42 | 6 | 6 |

第一次 union 批次仅遍历 8 个旧端口、迁移 32 个事实引用；全局仍有 56 个
活跃桶。原型并未实现精确的两个交叉乘积增量，因此整桶 144 次检查中
48 次是已有结果。无相同 k 的合并也暴露了保守标脏的无效补查。

表中普通 consumer 候选来自对普通运行前状态的独立 clone 开启诊断 trace，
不是普通执行的计时结果。所有数字是枚举次数，不是耗时或速度比。

## 预算与回退

| 每桶本地预算 | 第一次 union 的本地枚举 | 回退桶数 | 原生调用数 | 回退候选 |
|---|---:|---:|---:|---:|
| 不限 | 144 | 0 | 0 | 0 |
| 8 | 0 | 4 | 1 | 144 |
| 0 | 0 | 4 | 1 | 144 |

每阶段结束 Pending 都为零。不限、8、0 三种预算都得到完全相同的 Out。
每桶预算不是每阶段总预算：例如四个桶各有 4 对，预算 8 时仍本地枚举
16 对。它限制本地枚举工作，而不是整个系统内存；原生回退及其 trace
仍可能处理大量候选。

共享索引在最终阶段额外持有 257 个事实引用、56 个反向端口项、3 个
union 父链接；Pending 与脏集合在 flush 后为空。这里只报告逻辑项数量，
未测 allocator/RSS。缓存复制了原生事实的索引，不能当作 e-graph 压缩。

## 接下来应怎样使用

适合把它作为 block 快捷路径的失效/回退机制，而不是另造一个更慢的
全局 matcher。直接新增事实应保留原有 delta 通知，不必整桶重扫；union
时若要进一步节省工作，再实现跨合并前分区的配对增量，并计入其维护
成本。高扇出时继续回退，避免快捷路径无限保留复杂历史。

## 复现

```
CARGO_INCREMENTAL=0 cargo test --bin union_dirty
CARGO_INCREMENTAL=0 cargo run --bin union_dirty -- experiments/union_dirty/results.json
```

原生程序、数据生成、缓存、回退及逐元组断言都在
`src/bin/union_dirty.rs`；此改动仅为实验基础设施。
