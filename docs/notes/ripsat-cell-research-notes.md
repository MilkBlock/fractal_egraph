# RipSatCell：历史、闭包、状态转移与白名单执行

修订日期：2026-10-05。根据原笔记逐条修订，保留 1–46 编号。本文是研究定义与设计笔记，不是功能已实现清单，也不是性能证明。原始附件保留不变。

## 当前术语

| 术语 | 本文含义 |
|---|---|
| tier0 egraph | 原始程序的事实、表达式和等价关系所在的执行图 |
| rule application / apply | 在具体 binding 下执行规则；逻辑 match、动作执行与已提交 effect 分开统计 |
| rule composition | 多次 apply 及其 binding、依赖、条件和 effect 的组合；不默认是一条链 |
| relative binding | 后继绑定相对前驱接口、产出及外部输入的有类型映射；不是数值加法 |
| coarse / smooth application | 相对于选定局部上下文，是否还需要引入外部事实、等价关系或其他执行条件；不是规则的固有分类 |
| CoarseLayer / SmoothLayer | 对历史应用的分组描述；CSCS、CCSS 保留为组合形式，不作为唯一语义表示 |
| ripen | 在明确的输入接口、阶段、规则环境和 schedule 下推进局部推理；可能完成，也可能 unfinished |
| saturated rule composition | 在声明契约下完成相应局部闭包的组合；对于有界协议须说明完成的是协议，而非任意规则全局不动点 |
| RipSatCell | 局部状态及其输入、导出接口、阶段契约和 effect 的封装；不表示对任意外界交互永久封闭 |
| RipenInput | 局部推理的符号边界参数，具有 sort、别名及条件；不是自动匹配任意值的 `_` 通配符 |
| Cell definition / instance | 共享的参数化主体／主体在具体 binding 下的实例 |
| RipSatCell egraph | 用等价类归一化 Cell 描述和已登记构造选择的元层图；区别于 Cell 内部的事实 egraph |
| FractalComb | 具有可参数化、可重复 binding/effect 规律的 composition 族；重复现象先作为候选 |
| trigger state / reentry | 启动规律所需的状态／触发结构再次出现；两者都不能单独证明无限生成 |
| bake | 从样例历史提取并验证阶段相关模板与转移，形成可冻结的库 |
| abstraction / fragment | 运行时 Cell 状态实例／该状态发布的、可用于白名单匹配的有类型接口节点 |
| tier2 / reduce | 参数化组合与数学归约的分析层称呼；不是简单给旧 tier1 多加一个计数变量 |

`closed-state` 不再作为主术语；按语境使用 saturated rule composition 或 RipSatCell。旧 `RipSatEgraph` 指主体时改为 RipSatCell，其内部图仍可称 ripened egraph。`HigherRule`、`FractalRule`、`FracComb` 统一为 FractalComb。`dominant/dominate` 作为关系统一写作 dominance / weak dominance，避免与控制流图 dominance 混淆。

## 逐条修订

### 1. Apply 的位置由 binding 和匹配证据确定

规则 R 在图 G 上先得到匹配集合 Match_R(G)，一次 apply 由具体 substitution σ 以及读取、条件和等价证据描述。树路径或参数 position 可辅助定位，但在共享、循环和 union 存在的 egraph 中不能代替完整 binding。

R_ex(G) 表示按指定执行语义处理这批匹配后提交效果的结果，不是把多个 R(G,σ) 做普通加法。后续变化启用的匹配是否继续执行，由 schedule 决定。

### 2. Relative binding 是映射，不是可加偏移

两次应用写成：

G₁ = Apply(R₁,G,σ₁)，σ₂ = Φ(σ₁,已提交 effect,外部输入,当前等价关系)，G₂ = Apply(R₂,G₁,σ₂)。

Φ 编码变量对应、AST 位置、别名、literal、primitive 条件和外部输入。仅在特别定义的索引空间中，部分变换才可能表示为加法或仿射映射。

### 3. 从历史提取可复用 binding；prefix 分块是历史方案

原先用 prefix/block 限制历史增长；当前不把这种划分作为 Cell 的语义前提。producer 是提供已读取事实或等价证据的前驱，不再使用含义不清的 rule_evers。

历史依赖可有多父汇合和分叉。任意截取子图不一定是可执行 composition：必须补齐外部义务，保留动作顺序、版本与阶段边界。按具体事件版本展开的因果历史可成 DAG，但静态规则图、状态图和 egraph 可以有环。

同一状态可以保留多个构造选择，不必强制挑一个 prefix 进化。哈希用于索引、筛选和去重候选，不能证明 binding 等价或降低实际信息量。babble/library learning 是曾探索的可选路线，不是当前主流程依赖。

### 4. Coarse 与 smooth 相对于上下文定义

后继 apply 的所有必要读取、等价与条件由选定上下文提供时，称 smooth；还需要上下文外的义务时，称 coarse。smooth 不要求仅由紧邻前一条规则的 RHS 提供。

分类依赖具体实例和接口选择。同一规则可以既有 coarse 实例又有 smooth 实例。两类都可能分叉，不能断言 coarse 必然更有用或 smooth 分叉总是较少。

### 5. FractalComb 是可参数化的规律

希望把重复的规则、binding 变换和 effect 模式表示为一个参数化组合，而非枚举所有展开。计数、分支结构、接口增长和执行条件都可能是参数。

有限样例中的重复只给出候选。cost 可帮助选择表示，但不能证明终止、闭包或语义等价。

### 6. Binding 等价与 effect 等价必须分开

两次交换可使输入输出项映射回到原位，但第一次交换可能已经加入新 e-node 和等价关系。因此 Swap;Swap 不自动等于“不修改 egraph”。

在固定位置、普通集合式插入与 union、无新鲜分配或其他状态变化、且没有相关外部干扰时，后续交换可能不再产生新 effect；此时不同长度的轨迹可有相同闭包效果。不能把 Swap⁴=Swap² 或 E;E=E 无条件推广到任意规则和 binding。

FractalComb 启动前可能经历 effect 积累。trigger state 应包含使后续规律有效的接口和条件，而非只记录一段规则名称。

### 7. FractalComb 一般不交换，也不正交

“注入 A 的 trigger state → 执行 A → 注入 B 的条件 → 执行 B”是一种可能的分解，不是普遍调度形态。实际可能交错、汇合和多位置分叉。

不同 binding 会改变启动义务和后继结构。组合等价必须比较 binding、effect 与阶段条件，不能只比较出现次数。

### 8. 区分覆盖率、表示压缩和物理内存

LHS/RHS 探针可发现匹配实例，但“实例数 × 模式节点数”会重复计算重叠节点，也可能因参数投影合并实例。覆盖率应按实际可见 fact/e-node 身份取并集；e-class 覆盖单独统计，并固定快照和 canonicalization 口径。

覆盖率不是压缩率。物理压缩需计入库、binding、索引、元数据、缓存及峰值内存。加速需报告查询、动作、rebuild、准备和提取时间。同规模节点比较必须同时报告 extraction 质量。

### 9. 低覆盖率有多种解释

可能来自模板不足、接口表示弱、阶段不匹配、回放或导出失败，也可能来自真实结构差异。增加递归深度不保证改善。

可用 1、2、4、8 等有限深度对照研究具体族；不能把有限实验直接提升为无限规律。egglog 的 schedule 可以重复或 saturate 一个 ruleset，并不存在必然偏爱 ABAB 而排斥重复 A 的统一规律。

### 10. 参数化重复与 reduce

用 Iterate(n,T,state,binding) 表示已定义的转移 T 连续 n 次执行，不用有歧义的幂次嵌套。稳定的是参数化 relative-binding 规律，具体值可以不断变化；多 apply point 可能形成分叉递归。

reduce 将已证明的重复计算改写为更紧凑的表达式。例如在适当算术域、步数和条件下，f(a)→f(a−1)+m 的 n 步终点可写成 f(a−n)+n·m。

终点项等价不等于整个 egraph effect 等价。中间事实若能触发其他规则，省略其物化必须另有语义依据。严格浮点、溢出和执行条件也必须明确。

### 11. 包含、等价与价值排序分开

结构包含需要保持 sort、literal、别名和接口的映射；等价还依赖阶段与规则环境；存储或执行价值需要成本测量。更多节点或更多 apply 点不自动意味着 dominance 或更优。

egraph 的 union 表达等价，不自动计算所有包含关系；包含应保存在独立的有方向关系中。图结构匹配也不能单独证明条件蕴含。

### 12. “耗散”不是把 fact 从单调图中消耗掉

五个 1 的连续加法能形成有限归约过程，但 hashcons 后可能只有一个 Num(1) 节点被多次引用。可耗尽的是序列位置、剩余长度或可执行条件，不是 Num(1) 的物理副本。

称 dissipative FractalComb 时，必须说明限制继续展开的资源、参数或条件。读取外部 fact 通常不会删除该 fact。

### 13. Binding 有因果偏序，但需显式接口

在一个已记录的事件展开中，后继可以使用先前已提交的值；多个并行来源需要汇合。该偏序不自动解决变量作用域、fresh value、接口别名及不同阶段的可见性。

循环状态图可以按事件版本展开为因果 DAG，不能因此宣称状态图本身无环。

### 14. 从递归模式到数组是需要定义的抽象

受有限序列驱动的 FractalComb 可能被解释为 fold/reduce，但并非每种耗散组合都天然是数组。必须明确索引、顺序、长度、重复元素、依赖与累积操作。

数组成为 first-class 需要显式类型和运算语义。blocking、并行 scan 和重排还需结合律、独立性或其他证明；无限序列归约还需要适当的定义或收敛条件。

### 15. FlashAttention 是远期研究目标，不是已推导结论

softmax 的稳定形式为 exp(xᵢ−m)/Σⱼexp(xⱼ−m)，m=maxⱼxⱼ；注意力还需要对 value 向量做加权累积。

在实数模型中，两个块的摘要 (m,ℓ,o) 可以按下式合并：m=max(m₁,m₂)，ℓ=exp(m₁−m)ℓ₁+exp(m₂−m)ℓ₂，o=exp(m₁−m)o₁+exp(m₂−m)o₂，最终输出 o/ℓ。

这提供可组合摘要的思路，但不自动得到 FlashAttention。还需表示 QKᵀ、mask、尺度、内存层级、分块、数据复用及数值误差，证明合法调度并验证性能。不能仅用“指数与 max／乘除法的最优子结构”概括整个推导。

### 16. Bake 从代表性历史学习，不承诺覆盖所有未来样例

用多个训练样例收集阶段相关的 apply 历史、Cell 和转移。冻结库后在 held-out 输入验证泛化，区分观察模式与已认证可执行转移。

冻结白名单是当前优先实验方式。运行时自动补库是可选扩展，不是默认要求；若补库，必须考虑旧状态如何重新检查新加入的转移。

### 17. 库的价值来自节省的搜索与保留的质量

Coarse 的输入义务确实携带依赖信息，但不能认为 RHS 都能免费或自动由 smooth 推出。RHS 的 primitive、fresh、union、更新和阶段 effect 同样重要。

比较结构共享、接口成本、查询成本及 extraction 质量。trigger state 是明确的启动契约，不是可以随意擦除的杂项。

### 18. 用依赖图和接口表达组合，不强制线性链

任意 composition 可以选择某种合法执行顺序，但不能据此抹去多父依赖、分叉及阶段限制。空前缀的首个需要外部事实的 apply 通常是 coarse；无条件初始化规则是例外。

CoarseLayer/SmoothLayer 可作历史分组。是否同层、是否跨层不决定语义；决定因素是读取从哪里获得、哪些义务被接口显式化。共享元素不能单独证明两段执行可以交换或合并。

时间上相近的 apply 不一定空间相近，semi-naive 也不保证这种局部性。

### 19. CSCS 与 CCSS 是两类组合方式

CSCS 表示前一段局部结果为后续 coarse 交互提供上下文；CCSS 表示先组合 coarse 输入，再在合法条件下共同推进。

两种重组只有在外部输入、binding、条件、effect 和阶段顺序一致时才能比较。存在交点可以提供锚定线索，但不是合并充分条件；没有共享节点也可能由后来的 consumer 或外部关系明确连接。

### 20. 历史架构与当前架构区分

旧 prefix 分块、单链 tier1 egraph 和 babble 驱动选择不再作为当前语义基础。Layer 描述仍可用于组织历史。

当前 RipSatCell egraph 是新的元层归一化对象：节点描述 Cell 的构造，e-class 合并经过契约验证的等价描述。它不是把旧的 rule-chain egraph 原样恢复，也不必把所有组合压成 CS 链。

### 21. Ripen 的输入和完成条件必须显式

ripen 注入 coarse 输入及必要上下文，以有类型的 RipenInput 表达可泛化参数，按指定阶段协议推进。

完成不应只由运行时间短来认定。对正向单调规则集可检查局部不动点；对于 repeat、延迟提交和 cleanup 协议，应记录完成的是哪段协议，不能称为任意规则全局 saturation。

组合相交时，按实际 binding 和 effect 去重；不能只按规则名去重。无交点时由明确的 consumer 依赖建立连接，不自动枚举所有组合。fully equivalent 指归一化描述相同；ripened equivalent 指在匹配接口与环境契约下，完成状态具有已验证的等价关系。观察到相似快照不够。

### 22. Weak dominance 是方向性的触发包含

约定 A weak-dominates B：在 A 的已观察局部状态中，找到满足 B 输入契约的触发结构及 binding。该关系不声称 A 已完整包含 B 的饱和结果，也不保证可替换或终止。

在统一语义下若另行定义出传递的包含预序，可对互相包含做商，再讨论严格关系的 DAG。不可比性并不导致环；有限状态也可能因接口／条件不同而不可比。weak dominance 不要求推广成这种强关系。

### 23. 自重入不是终止判定

在新的位置找到自身触发结构，且涉及新的 binding 或 effect，可标为 non-trivial reentry 候选。“未登记”必须相对 canonical binding 与效果定义，不能只按新的事件 ID 判断。

自重入既不证明无限增长，也不证明会有限饱和。时间或空间上限仅产生 unfinished 观察；例如 50 ms、200K facts 是实验保护配置，不是数学性质。

### 24. 未发现的等价入口始终可能存在

一个 RipSatCell 可能有多个不同的 coarse 入口。当前目录只记录已发现并验证的那些；不能据此声称所有入口都已找到。使用“尚未发现的等价入口”代替含糊的 unfounded 类别，不把未知当成已证明存在的关系。

### 25. CSCS 是递归发现线索，不是分类证明

C₁S₁C₂S₂ 中重新出现 C₁ 的输入模式，只构成递归候选。还需比较 relative binding、阶段、effect 增长和外部需求，才能归纳 FractalComb。

C₂ weak-dominates C₁ 不足以证明 node-effect dissipative。多触发点应记录在参数化依赖结构中，不枚举所有可能线性顺序；不能仅因某处已 weak-dominated 就删除它可能带来的新绑定或效果。

### 26. FractalComb 分类

- 自维持／infi 候选：无需新的外部输入即可反复启用。只有证明能持续产生新相关效果，才能称无限生成；幂等循环不是无限增长。
- node-effect dissipative：后续展开需要额外的外部事实／节点输入，不意味着读取会物理消耗节点，也不单独证明终止。
- 条件／参数限制型 dissipative：长度、边界、guard 或其他状态限制继续执行；存在递减的良基度量时才有相应终止依据。

擦除 length 等状态可用于抽象归类，但可能把有限过程变成抽象的无限过程。因此只能先收进重入候选，执行前恢复条件。不能把影响分支或 apply 点数量的已知结构差异一起擦掉。

### 27. Trivial 与 non-trivial reentry

Trivial reentry 指回到已解释的 binding/effect 状态，没有相关新进展，例如固定上下文中的交换幂等。

Non-trivial reentry 指触发模式再次出现并伴随尚未解释的 binding 或 effect 变化。它仍是观察分类，需要进一步区分有限增长、多叉展开、边界注入和无限生成。

### 28. Reuse Graph 与 Cell egraph 各司其职

Reuse Graph 存储共享主体、实例映射、残差和包含关系；Cell egraph 归一化等价状态描述与构造选择。weak dominance 或 reentry 可以提示共享机会，但不足以直接授权物理替换。

生成前驱、结构包含和等价不是同一种边。大 Cell 内出现小 Cell，不要求它历史上真的由该小 Cell 构造而来。

### 29. Residual 需要统一身份，hashcons 不只服务 union

hashcons 为具有相同算子及 canonical 子项的节点提供结构去重。union 改变等价关系，rebuild 可能使先前不同的节点键相同；Join 则依据可见行、索引和 canonical 值查询，几者相互关联。

比较 R_A、R_B、R_C 时，先建立兼容的接口映射 θ_A、θ_B，再将 C 中尚未由 θ_A(R_A)∪θ_B(R_B) 表示的事实视为 residual；等价变化、可见性和更新义务另行记录，不能只做本地 ID 的集合差。

inherent residual 可定义为相对选定组成部分仍未解释的部分，它依赖分解方式。Bloom filter 可快速排除不可能的成员，阳性必须核验，不能用于删除事实或证明等价。这样的残差表示与增量数据流有关，但不会自动产生正确的维护算法。

### 30. RipenInput 槽位不隐含不相等

不同槽位是不同参数名，不代表实例中必须取不同 e-class。需要明确别名允许关系、显式相等／不等条件和 alias specialization。

两个输入后来 union，可能使 Cell 启用新的内部匹配，不能仅合并参数 ID 就认定原闭包仍完整。可以把这种等价输入作为转移 effect，但须保留实际条件。

### 31. 等价传播与封装变化

x=y 蕴含 f(x)=f(y) 是 congruence；不自动蕴含 f 的逆向单射性质。union 可能经父引用和 rebuild 传播，并使旧事实产生新连接。

这可能是封装更新的重要来源，但“最大的推手”需要测量，不能当既定事实。内部饱和不等于对所有外部等价变化封闭。

### 32. 槽位对称性必须保持完整接口语义

可研究保持闭包结构、sort、literal、约束与导出端口的槽位置换。slotted egraph 是候选工具，不是唯一方法，也不能自动证明任意参数交换合法。

多 root 是多端口接口问题，可以明确建模，并不天然使方法不可用。

### 33. Slotted egraph 资料作为待核验参考

原笔记保留的博客链接：https://zhuanlan.zhihu.com/p/1962133733982336437 。本次未核验链接内容，不将其实现声明或性能结论作为证据。实现和论文应分别核验，尤其是多接口、变量 support 和等价条件。

### 34. 对称归一化的收益需要独立测量

区分变量 alpha-renaming、合法槽位置换、结构同构与语义等价。可比较开启／关闭对称归一化后的不同状态数、binding 成本及运行耗时。

不能宣称输入对称性只能由 slotted egraph 处理，也不能因两个 Cell 看起来同构就忽略 literal、阶段或条件差异。

### 35. 动态实例应表示已知状态与新增义务

Cell 间边界 apply、输入具体化和 union 都可能启用后继 Cell。研究表示为“已知状态＋边界 binding＋待处理变化”，通过已认证转移推进。

已知转移可直接传递 binding，未知变化不能伪装成已完成状态。状态登记、参数 canonicalization 与语义闭包更新是不同操作，不能混为一谈。

### 36. Semi-naive 的成本与保证

Semi-naive 按规则自己的增量进度处理变化，不是所有规则共享一个消费即清空的队列。二元 Join 的典型增量分解为 ΔP⋈Q_all 与 P_old⋈ΔQ；具体实现不必枚举完整笛卡尔积。

同一事实通常由表去重，但仍可由不同匹配重复推导；“不会重复进表”不等于“动作只执行一次”。完整成本包含失败候选搜索、成功匹配、primitive/RHS、插入、merge/rebuild、维护及提取。

“前五轮每事实约一次匹配”“交换律为 1.7”等旧数字缺少本笔记中的可复核口径，保留为待核验历史观察，不作为普遍结论。AC 规范化可能减少枚举，但改变可见表示和匹配机会，需要相应语义支持。

### 37. Fragment 表示可用能力，不是全局免查询声明

由已知状态或转移直接发布 fragment，表达具体接口事实和关联；条件必须足以支持后继白名单匹配。不能把“某 Cell 含有一个匹配”提升为“所有该类匹配都已覆盖”。

若通过额外完整 Join 构建 fragment，再保留原查询，可能只增加维护成本。要分别测生产、维护和消费成本。

### 38. Canonicalization 的时机不是任意的

需要 canonical key 的查询和去重必须满足相应一致性契约。立即 canonicalize 可以减少部分冗余，但频繁更新也有成本；延迟 rebuild 需要明确的批次与可见性边界。

不能认为在首次插入时 canonicalize 一次，就能涵盖未来的 union。

### 39. 缩小规则集合不等于单调减少所有统计量

在固定的正向单调语义及适当闭包比较下，限制规则通常减少可推导信息。但原始 e-node 数、e-class 数、已选提取结果和执行时间不必按同一方向变化，特别是存在 union、subsume、有限 schedule 和顺序敏感 merge 时。

比较应使用明确语义映射和质量指标，而不是假定 e-node 与 e-class 差距总是不断扩大。

### 40. 不能用假等价获得真实压缩

未经证明的 union 会改变匹配和可提取程序，通常不存在便宜的逆操作恢复原语义。可在独立抽象层做有损分组，并保留 concretization／验证边界，但不得把它当作 tier0 的真实等价。

若定义 Cell 距离，应明确是描述编辑距离、接口差异还是转移成本；它们不是自动等价的概念。

### 41. Summary 必须有统一语义

参数化分析需要明确的 summary DSL、输入输出契约和归约规则。统计归纳提供候选，验证提供可执行保证。

同一类 summary 应共享变量作用域、effect 和阶段定义，不能仅以显示公式相似就合并。

### 42. Coarse apply 可以扩展接口，不是变量凭空分裂

新外部输入可能使状态所需端口增加；旧 binding 通过显式映射接入新接口。不需要无条件重写系统里所有实例。

slot/support 数量、普通 constructor arity 和 Cell 边界端口数是不同概念，应分别记录。接口发生别名或新增端口时，需要定义其与既有状态的关系。

### 43. 接口增长规律是 FractalComb 的一个维度

端口数量按层增长、slot 映射重复、分支模板稳定，都可辅助识别规律。但仅凭 arity 数列不足以证明相同转移或递归性质。

所谓去除多余 smooth apply，需要证明它不改变后续可观察的 fact、等价、可见性和阶段行为。

### 44. Coarse 上下文是带证据的多接口拼接

一个 coarse composition 的上下文可能含多个根、LHS 读取、已有外部事实、提交后的 RHS effect 和 union 证据。不能简单把每条规则的 LHS、RHS 文本并起来，就当成同一时刻已经存在的事实。

普通 egraph 和 slotted 表示都需保留时序及接口映射。graft 可以发生在前驱 root、RipenInput 或内部导出位置，也可以由多个前驱共同提供 LHS。只支持竖向链是表示限制，不是语义限制。

### 45. 可编译闭包共享的核心假设

要验证的是：大 Cell 的增长能否主要由少量重复的边界组合解释，而不只是小模式经常出现。

一种目标表示为 C=Sat_contract(⋃ᵢθᵢ(Cᵢ)∪F_boundary)，并单独记录新等价及残差。接口参数、残差、状态维护和寻找合法连接的成本，都要小于展开执行节省的成本。

状态 egraph 可保存多个已登记构造路径；历史路径、结构包含和已验证等价分别展示。可视化展示的是已登记选择，不声称枚举所有可能推理路径；循环应显式表示而非无限展开。高入度前驱可用于浏览排序，不作为保证强度排序。

### 46. 当前研究方向：阶段感知的 Cell 白名单执行

Semi-naive 是增量执行方法，本身不应笼统称为不完备或错误保证；规则语言、schedule、终止条件和实现共同决定可得到什么结果。

我们主动缩小探索空间：冻结 bake 库，只保证在声明的阶段协议下公平执行满足接口条件的库内转移，不保证执行全部原始 eggcc 规则。每个执行的转移仍须正确；不能用少探索来放宽 effect 的合法性。

rule-level 的目标循环为：创建 abstraction → 直接发布白名单 fragment → 匹配 fragment 和边界条件 → 执行合法转移 → 发布后继 fragment。原始优化规则不同时作为无条件全局 fallback；但类型、上下文、延迟 union 等阶段义务必须保留或被经过验证的实现替代。

对 eggcc，首先从 history 保留 pass、schedule 调用位置、ruleset、读取版本与提交 effect，再在相同协议下 ripen。相同 ruleset 的多次调用不自动等价，不同阶段也不应仅因最终形状相同就共享可执行转移。

研究验收比较：原版、相同白名单但普通执行、白名单＋Cell 转移。记录达到相同逻辑节点规模的时间，同时比较 extraction 质量、最终程序正确性、实际程序性能、库大小与运行时内存。不预先承诺“极快且无质量损失”。

## 当前证据与未实现部分

本节仅概括本轮对话已核查的保存结果，不代替一次新 benchmark：旧 44 个快照去掉背景项后为 43 个模式；后来 121 个完成观察去掉背景项后为 120 个条目；合并库是 163 个模式条目，不是 163 个不同认证 Cell 族。约 20% 的某项数字是特定有效 apply 签名命中率，不能笼统称为结构覆盖率。

现有观察覆盖、认证闭包、可执行转移和实际 Join 节省是四个不同指标。动态实例的任意外部变化维护、一般化的 fragment 白名单生成和上述执行契约，仍需逐项验证。不能从“历史上出现过”直接跳到“所有新实例均可无查询复用”。
