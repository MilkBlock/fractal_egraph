# 按上下文深度推进的匹配 frontier

独立 CPU 参考实现：沿用两个参数化 math Cell、八个向量实例和因式提取边界。
四条原规则负责 Bake；本版没有把任意 ruleset 编译成通用分层引擎，也不是 GPU 实现。

目标：浅层能够完成的输出，已经证明不可能的排除，未知的保留并沿相对接线继续。
没有 beam、Top-k、候选预算或人为观察深度上限。深度由 Bake 接口表达式决定。

## 上下文和状态单位

仍以外部提供 `Add(left_port,right_port)` 为前提，检查：

```text
Add(Mul(k,u), Mul(k,v)) → Mul(k, Add(u,v))
```

Bake 已经知道所有 enode 备选，因此可以提前证明哪些锚点没有 Mul，以及哪些因子
树形不可能相等。运行时不重复检查这些拓扑。

动态深度定义在两个 k 的接口表达式中：

- 深度 0：k 为 Input，比较其身份；
- 深度 1：Add 直接连接的 Input；
- 深度 2：嵌套 Add 内部的 Input。

同一个输出 binding 通道可能有多种交换排列；将等价的相对接线合并为 OR 分支。
每个分支保留一整组条件，不将不同分支满足的一半拼成完整匹配。

输出 binding 通道有三态：

```text
complete：至少一个完整接线分支的条件全部成立
rejected：所有接线分支都已被证明失败
continue：没有已完成分支，但至少一个分支仍然可能补全
```

未知条件不是 false。同一触点对的一条 binding 完成，不会取消该触点对的其他 binding。
已完成／排除的通道不重新进入 frontier。失败的分支也不重新进入下一层。

## 同形批处理

从当前层活跃分支收集所需条件，以源向量坐标 `(实例,相对槽位)` 标识，不以实际 binding
值建立索引。相同左右槽位布局、同一编码维度的条件组成矩阵批次，计算 `L Rᵀ / 16`。

前一层算过的条件保留；其他浅层任务已计算的条件也可直接用于较深位置。实例编码在
一次运行内不可变，缓存不跨未知 union 或更新继续使用。

矩阵外积可能额外算出本批次未要求的位置。本版明确统计：

- 本层需要的唯一条件数；
- 实际矩阵位置数和乘加数（包括多算的点）；
- 非请求位置以及矩阵内重算的已知条件；
- 输入矩阵元素数量（逻辑数值规模，不是硬件访存测量）；
- Python 状态分类次数和证据读取次数。

没有只报告稀疏请求数、却隐去稠密批次的额外成本。

## root-only：逐层确实减少了数值工作

8 个 root 提供 64 个 Add 上下文，16 个有向 Mul 接口形成 256 个完整 binding 通道候选。
同实例输入互异是原向量实验的契约，因此部分相等／不等在 Bake 接线下已知。

| 阶段 | 累计完成 | 累计排除 | 继续 | 本层矩阵乘加 |
| --- | ---: | ---: | ---: | ---: |
| Bake 保证 | 16 | 160 | 80 | 0 |
| 深度 0 | 30 | 202 | 24 | 784 |
| 深度 1 | 36 | 218 | 2 | 720 |
| 深度 2 | 38 | 218 | 0 | 64 |

实际例子：

```text
(a+b)+c 与 (a+c)+b：深度 1 的 c≠b 已排除，不读更深 Add。
(d+e)+f 与 (e+d)+f：深度 1 的 f=f 不足以完成；保留到深度 2。
```

与**相同接线、相同静态化简、相同矩阵分组策略，只是一次读取所有深度**的对照相比：

| 实际计数 | 一次性 | 分层 |
| --- | ---: | ---: |
| 条件请求（含多个使用者） | 176 | 136 |
| 缺失的唯一条件 | 82 | 62 |
| 矩阵乘加 | 3,232 | 1,568 |
| 输入矩阵元素 | 1,088 | 832 |
| 矩阵批次数 | 6 | 10 |
| 非请求矩阵位置 | 100 | 18 |
| 状态分类次数 | 336 | 362 |

乘加减少约 51.5%，但批次数与状态管理增加。没有测量 GPU 启动、搬运、compaction 的
时间，不能把这个数字当作运行时间加速或神经网络效率百分比。

## 全部内部触点：没有额外矩阵收益

72 个 root/non-root 锚点提供 5,184 个 Add 上下文。Bake 排除没有 Mul 的 4,160 个，
剩下 1,024 个；64 个 Mul 接口形成 4,096 个完整 binding 通道候选。

Bake 后 168 个完成、1,512 个排除、2,416 个未知。深度 0 完成后已经全部决定：
462 个完成、3,634 个排除。

原因不是把未知当作失败：大量内部 Mul 的浅层查询已经计算了更深的复合因子需要的
输入相等条件，因此这些条件可以共享。深度 1/2 不需要任何新矩阵计算。

| 实际计数 | 一次性 | 分层 |
| --- | ---: | ---: |
| 矩阵乘加 | 9,504 | 9,504 |
| 批次数 | 16 | 16 |
| 条件请求 | 2,644 | 2,348 |

这里没有分层带来的矩阵节省，不能只选择 root-only 的有利结果。

## 正确性与范围

分层与一次性同算法逐项相同；也与前一版完整张量收缩逐项相同。原生 oracle 显式提供
相同的 5,184 个 Add 上下文，得到 462 条带触点标签的完整 binding；去重后为 110 条。
原始规则执行后的所有目标等价检查通过。这是条件 graft 实验，不是原输入已有匹配数。

测试覆盖未知状态保留、深层继续、错误外层提前排除、已结束状态不重启、多个 binding
不相互覆盖、批次相对接线一致性及真实稠密计算量。禁用原 matcher、constructor 查询、
向量解码、旧完整评分与完整 Spine 枚举后，分层内核仍能完成。

仍然限于两个模板、有限 16 元素域、实例内输入互异。没有动态 union 更新，没有新 Cell
编码反馈。frontier、分组和结果 compaction 由 Python 完成；仅数值比较是矩阵运算。

## 复现

```sh
python3 experiments/cell_spine/layered_context/demo.py \
  --output out/layered-context-next

# 已构建当前 native 工具时可加 --skip-build。
python3 -m unittest experiments.cell_spine.layered_context.test_demo -v
```

输出目录必须不存在；默认离线构建；Python 使用标准库。
`index.html` 展示每层三态、同形批次和完整成本对照；`report.json` 保存阶段快照和计数；
`prepared.json` 是从 Bake 提取的上下文层级；`graft-check.egg` 是原生验证程序。
