# Cell credit：给结论记功，给执行记成本

## 要比较的两条路径

固定任务、规则调度、输出正确性要求和公共执行能力 B。B 包括已有索引、普通空表短路、函数键查找、通用查询编译、后端及可共同使用的依赖订阅。不能故意让对照缺少这些基础能力，再把差异奖励给 Cell。

设当前其余库为 L，待评估 Cell 或证明组为 C：

```text
credit(C | L) = J(B, L) - J(B, L + C)
```

J 使用同口径推理时间，包含本次所需的识别、版本验证、更新维护、剩余搜索、交接、原生 effects。维护成本已在 J 内，不再扣第二次。setup、Bake 和 extraction 单列；若要评估跨 N 次复用，显式减去新增的一次性成本，不把字节和秒任意加权。

Cell 方案可以改变合理的布局或执行计划，但两边必须使用相同的公共优化能力，并将布局变化的成本计入方案。当前提供的是更窄的联合证明组实验，特意固定查询计划和后端位置以隔离原因。

## 三种账不能混

1. **公共执行账**：空表短路、固定取值、CPU/GPU 路由、普通端口缓存。Get 的新读取与 Switch 的空回答在两条路径中都存在。它们不因模块名叫 Cell 就领取闭包 credit。
2. **证明消费账**：一个版本有效的 Cell 结论被实际用来免去一次搜索/饱和义务。只命中一个 Cell、发现一段结构、读到一个缓存值都不等于这种消费。
3. **净收益账**：上面的受控反事实 J 差值。消费次数不直接等于节省的时间；同样允许负 credit。

基于全库开/关的规则工作量变化，不能回推出每个 Cell 的净收益。旧 `cell-value` 的 schema v2 将这些字段称为 `observed_*_delta_share`，`cell_specific_credit` 保持未归因。

## 共享和重叠

每项被跳过的义务只能在执行账中计一次。相同结论的等价 spine 应共享一个证明身份；大 Cell 用到小 Cell 的结论时，不能让两者都领取同一份跳过工作的全部 credit。共享证明的维护也只记一次。

设计价值依赖 L。两份可互相替代的 Cell 在完整库中都可能具有零删除边际，不能据此同时删掉两份；应先归为替代组，或者每删一个后重新评估。不能将互相依赖的组内 credit 简单相加成库的价值。

未来逐 Cell 的消费证据至少要包含：Cell/证明身份、有效版本/前提、消费的查询或饱和边界、被替代义务的身份、实际采用者和依赖证明。可以在实际消费点聚合计数，无需重新保存完整 match history。当前**尚未实现**一般的逐义务唯一归属与逐 Cell 时间消融，不能声称已有。

## 当前已实现的受控实验

`CELL_JOINT_PROOFS=0`：保留 CPU 参数化 dataflow、普通查询接管、根接线、订阅、端口缓存和原生提交。关闭 joint fresh-DAG/静止宏、uniform-cost 候选退役和 Smaller 比较闭包；不支付这些证明的运行期检查/状态维护。

`CELL_JOINT_PROOFS=1`：同一执行器，开启上述证明组。两边都装相同 source programs，公共查询和 GPU 配置保持一致。

`cell-credit --baseline DIR --candidate DIR` 拒绝错误/混合二进制、插桩、不同公共配置、关闭通用查询服务、未真正消费证明的记录。只将净收益记给 `terms-joint-closure-proofs` 证明组，单个 Cell 的 credit 仍未测。它也不代表自动 Bake 已发现这些证明：目前是已检查的参数化规则组契约。

这给出了一个可复用的实验契约。后续 Cell 设计应接入各自的证明开关与消费身份，而不是继续用“从 GPU 移除了多少查询”作为奖励。
