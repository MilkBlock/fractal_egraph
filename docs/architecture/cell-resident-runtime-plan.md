# Cell 常驻推理运行时：完整实施计划

状态：**设计计划，尚未实现本文件提出的新运行时**。日期：2026-10-31。
依据：当前工作区，HEAD `f98309f`；本次只读实现并编写计划，没有运行性能测试。

## 1. 目标与验收契约

运行时以“共享 Cell 配方 + 实例参数 + 精确状态 + 待处理 effect”为主要表示。
覆盖区域的正常推理不先生成全部全局关系表行，再通过 Free Join 找回这些结构。
输入导入、调试导出和独立参考执行可以使用旧表；必须与新运行时的热路径分开计时。

主要验收要求是用户已选择的两点：

1. **Soundness**：每个已公开的构造、函数更新、union 和可见性变更，都有被允许的规则执行依据。
2. **目标后端逐轮可复现**：同输入、同编译产物、同目标执行配置下，各实际 Run 的可观察结果及稳定事件顺序可复现。

不要求真实 Pass 3 与原 CPU 的全部非合流选择、物理编号或匹配顺序相同。
但 soundness 不等于“可以省略问题”：覆盖不足、尚有未处理工作、未支持操作必须明确报告。
在声明覆盖完整且收敛的子集上，另做完整事实／函数值／等价关系／可见性对照。
真实应用还报告同等工作规模、extraction 成功率和质量，不能只比较越来越少的计算量。

对一个实例定义逻辑展开 `Expand(template, instance, visible_cut)`。它是可观察结构的含义，
不是要求每轮真的生成这张图。存储压缩、缓存淘汰、GPU 布局变化不得改变这个含义。
如果改变原选择策略，必须通过显式 source_sk 转换及产物声明表达，不能藏在执行器内。

### 必须成立的不变量

| 编号 | 不变量 |
|---|---|
| I1 | 每个引用有确定类型、身份空间和存活期；内存搬迁不改变身份 |
| I2 | 模板相同不意味着实例根相等；union 必须来自规则／congruence 依据 |
| I3 | 同一个 binding 的参数保持相关联；不能从不同实例或不同时刻拼凑成功条件 |
| I4 | 所有逻辑上存在的内部节点均可通过配方枚举，包括非 root 位置和回边 |
| I5 | 未就绪不等于不存在；未发现不等于无法匹配；未知不等于 false |
| I6 | set 的 proposed value 不等于 actual merged value；后继读取必须区分二者 |
| I7 | 相同键上的更新次数与必要顺序不能因 effect 去重丢失 |
| I8 | 行、函数结果和等价关系均受可见性约束，不能只给行增加 Stage 标签 |
| I9 | 旧输入变化不撤销已合法提交的历史结论；它只影响待执行工作和复用保证，除非源程序显式删除 |
| I10 | 缓存命中、规则执行、effect 请求、实际逻辑变更分别计数 |
| I11 | 资源不足、取消或未覆盖工作不能被报告为饱和完成 |
| I12 | 覆盖区域不调用原 `row_lookup/write_row/Free Join` 完成正常推理；残余搜索通过逻辑图接口执行并单列 |

## 3. 存储对象与身份

### 3.1 共享模板

```text
CellTemplate
  环境摘要：typed source / schema / merge / schedule / primitive ABI
  参数槽位：类型、相关性、alias 前提
  结构配方：constructor DAG／有限递归程序，包含全部可观察内部位置
  事实配方：relation、函数读取／更新、可见性操作
  执行程序：guard、精确算术、构造、更新、union、后继接线
  Stage 程序：合法激活位置、repeat/saturate 控制及读写版本要求
  边界目录：可提供的 operator、位置族、完整键和残余条件
  保证：已验证规则推导、未证明部分、运行时前提
```

模板是共享的程序，不是某次运行的终态快照。环境摘要只能检查产物一致性，不能代替语义证明。
历史观察负责发现候选，typed source 和独立校验负责证明配方；不能用有限样例拟合代替通用验证。

### 3.2 实例与执行帧分开

```text
CellInstance                       ActivationFrame
  template ID                       instance ID + StageToken + activation ID
  精确输入引用／数值                  当前指令、相关 binding、各输入就绪状态
  已提交的逻辑状态                    当前使用的端口版本
  子 Cell 连接及构造配方片段          未公开的构造／更新／union 请求
  当前公开端口及逻辑事实所有权        错误、挂起原因、已完成操作凭据
```

一个实例可以经历多个激活。**实例上的永久 done 位不足以判断以后是否应执行。**
执行完成的帧可以回收，但其产生的逻辑结构仍由实例、共享配方或其他持有者保存。
单独释放帧不能使已经存在的事实消失。

同类实例按 SoA 列存储：引用列、精确整数列、状态位、版本列分开布局但属于同一执行块。
每类布局列宽固定，实例行和必要的关联分支按实际需求分块增长。
不分配“全部事实 × 全部模板”，不为可能存在的所有 binding 预留矩阵行。

### 3.3 引用种类

| 引用 | 表示什么 | 什么时候需要 |
|---|---|---|
| `LocalRef(frame, slot[, item])` | 本激活中尚未统一身份的构造或计算结果 | 配方内部连续执行 |
| `NodeRef(instance, recipe_position[, item])` | 已有逻辑节点的稳定位置 | 共享内部节点、恢复图、extraction |
| `EClassHandle` | 全局相等关系中的稳定句柄 | 跨 Cell 身份比较、union、congruence |
| `FactRef` | 一条逻辑事实的身份／来源，不是物理行偏移 | 匹配证据、可见性、重复派发消除 |
| `FunctionKeyHandle` | 类型与完整参数键所指向的函数条目 | 订阅实际结果及进行冲突合并 |
| `ReadPortRef(key, cut)` | 在指定可见截面读取函数值的承诺／结果 | 跨阶段依赖、迟到输入 |
| `EffectId` | 一次获准执行的动作请求 | 重试幂等、保留非幂等更新次数 |

`item` 用于参数化生成族中的具体位置，不能把整个递归族当成一个具体节点。
虚拟 NodeRef 可以按需获得 EClassHandle；用稀疏 promotion 映射，不强制每个潜在内部位置都有独立 DSU 项。
参与相等比较、union 或全局接线时不能再拿“尚未提升”充当不相等。

编号只编码稳定的空间／块／槽位信息。槽位复用时加 generation 或延迟复用，防止 ABA。
当前代表、版本、Stage 和可见性不塞进不可变身份，而放在紧凑元数据列中。
不预先规定 64 位分割比例：先测容量及访问模式；局部引用优先相对 32 位，块元数据共享。
句柄的逻辑分配顺序不能依赖 GPU 线程先后抢到哪个 atomic ticket。
身份、generation 或版本计数耗尽时显式报错或进行有协议的 epoch 更换，不能静默回绕复用旧值。

### 3.4 实例重叠与共享

不同 Cell 可以描述同一个具体节点，也可以覆盖相互重叠的结构。
物理上允许多个配方引用，逻辑身份由精确结构键和已证明的等价关系决定。
不把每个节点强制归属唯一 Cell，也不因两个 Cell 模板相同就 union 实例根。
抽取、事件去重和匹配凭据按逻辑身份处理，而不是按“来自第几个 Cell”重复执行。

初始 IR 使用基础 Cell：直接保存输入构造、relation 和函数初值的精确参数。
初始不一定高度压缩。随着已证配方建立，逐步转移到更大的 Cell；替换存储所有权前验证逻辑展开一致。
共享配方确实可以省去大量行，但任意一百个独立状态位不能总被一个很小的状态 S 无损表达。
必须保留无法由配方推导的残余信息，并单独统计其内存。

## 4. 编译流水线与输出

沿用正式入口：

```text
source.egg → source_sk.egg → Analyze/Bake → source_sk_mk.egg
              ↓ 原生解析／类型检查／控制语义
           Shared Recipe IR
              ↓
  Cell storage + port + effect + schedule contracts
              ↓ 独立校验
  CPU reference layout / GPU layout + kernels
              ↓
           可直接加载的 artifact
```

新增 pass 按依赖排列：

1. **源语义展开**：保留声明、函数 merge、RHS 行为、Run/Repeat/Saturate、probe 和命令顺序。
   包括阶段之间的显式 fact/set/union 命令，不能只编译一段 schedule。
2. **Cell 结构与入口提取**：从 analyze 的实际 binding／effect 证据选择候选；从 typed rule 证明
   不变接线、参数变化、缺失输入与关联键。支持内部位置和多个入口。
3. **虚拟事实配方生成**：为可观察节点提供访问器、枚举器和 slot identity；保留生成族、容器与中间构造。
4. **读写依赖与 merge 分类**：区分构造、纯数值、函数结果读取、set、union、hide/delete；
   计算包含 merge 回调的传递 footprint。未知 footprint 标记 unknown，不当成空集。
5. **marker lowering**：共享 spine 发布器直接建立实例／端口接线；保留尚未就绪端口。
   marker 的全部相关参数必须可恢复。对“源码 view 已完整”与“Cell 内部推导已保证”分别认证。
6. **Schedule 编译**：生成带逻辑 occurrence 的控制程序和每个操作的发布条件，不把 finite repeat 改成 saturation。
7. **局部程序编译**：固定复制、算术、比较、构造配方和状态更新融合；纯可归约 merge 与有序 merge 分开。
8. **布局与批次选择**：先使用确定性基础布局；以后引入运行数据、求解器或学习选择布局。
   布局改变不能改变配方授权、相关 binding 或可见性。
9. **独立 verifier**：从源程序重建类型、依赖、Stage 权限和允许 effect；拒绝篡改的映射和越权 union。
10. **目标 lowering**：CPU 与 GPU 消费同一契约；target 报告支持、残余执行和未支持项。

建议新增 `cell-runtime-program.json`，包含模板、接口、函数策略、控制程序和能力清单；
二进制镜像存放真实运行所需的紧凑数组。JSON 是离线可读产物，不是每轮 GPU 通信格式。
已有 `recipe-program.json` 保留为源语义基准，不复制一套相互漂移的 query/effect 定义。

缓存键包含 source_sk/mk 内容、规则／merge 环境、primitive ABI、IR schema、编译 pass 版本、目标配置。
只改物理布局不重做 Bake；规则语义改变必须重新验证。所有阶段分别记录 receipt、耗时和产物校验和。

## 5. 单次激活和多阶段执行

### 5.1 启动与挂起

1. 输入导入事件或已公开 effect 触发共享 marker 发布器。
2. 按完整关联键查找／建立实例与激活帧，不逐模板扫描全图。
3. 绑定已经确定的参数，安装缺失端口订阅。
4. 执行所有当前就绪且获准的指令；后继直接读取同一块内结果。
5. 遇到未知函数回复、未授权 Stage 或边界 binding，挂起该依赖，不阻塞无关实例。
6. 输出必要 effect 请求；可保留为符号配方的构造不立即物化。
7. 合并完成后将实际回复写入端口；只调度因版本或就绪状态变化而受影响的指令。

工作队列按模板、指令段、激活 Stage 分批。队列记录真实就绪工作，不反复扫描所有帧。
工作本身可能需要连续多次执行；不能把 GPU 一个 kernel 的一次派发等同于一个完整 Cell。

### 5.2 事实、计算和发布有三个不同状态

```text
Prepared：配方／候选已准备，不能作为规则成立证据
Justified：当前激活下，规则输入和 guard 已有精确依据
Visible：其 effect 已经过冲突处理，并对指定消费者可见
```

后继可消费哪些内容由编译的依赖契约决定。
不能将一个 prepared 数值提案当成实际 merge 回复；不能以推测的 guard 对外发布 effect。
已经完成的纯结构／算术计算可留在块内，输入版本没变时不重复计算。

### 5.3 StageToken 和可见截面

`StageToken = (control position, occurrence, repeat/saturate stack, read cut)`。
不同实例可以共用控制描述，但不能只保存一个 ruleset 名称。

- 有限 `Run` 的 LHS 读取其规定的匹配截面；同 Run 新写入不能自动成为另一轮 LHS。
- RHS lookup-or-insert、函数读取和 merge 的 old/new 按源操作的语义单独建模；
  不能假定所有 RHS 读取都等于 LHS 快照，也不能让后继读到任意未来版本。
- 多阶段程序可以提前准备未来 patch。实际 effect 按编译的权限逐段公开，不重新搜索已知接线。
- `repeat 5` 是五次合法控制展开，不是无界闭包；嵌套 saturation 保留自己的迭代与退出条件。
- `until/check/extract` 等观察点只能看到其规定的公开截面。它们构成必要的发布／完成边界。

**特别注意：未来 union 也会改变旧节点的含义。**
不能把所有未来 union 写进同一个全局 parent 数组，再靠隐藏未来行维持 Stage 可见性。
采用“已公开等价关系 + 局部 union overlay”；需要旧截面的读者持有对应版本视图。
CPU 原型可以用持久化／写时复制分页及变更日志，GPU 保留受影响页和版本引用；
不为每个 Stage 复制整张图或整份 parent 数组。

没有观察者、无冲突且经认证可交换的段可以联合完成，再统一发布。
存在真实值依赖时仍要等待对应回复；这是依赖顺序，不要求 CPU 每次参与，也不要求全局表刷新。

### 5.4 执行凭据与固定点

凭据需要区分“这个激活中的动作已经提交”与“它的结论目前仍成立”。
`EffectId` 来自稳定的规则、关联 binding、激活实例和动作位置，重试同一个请求只提交一次。
不同获准激活的两次 `set` 不能因为值相同而合并成一次。

具体再激活条件由源规则的 delta／watermark 语义降低，不能简单使用
`(rule, root)` 作为永久完成缓存，也不能任何全局事件都刷新全部凭据。
union 后需归一化受影响的 binding／凭据键，防止重编号制造重复逻辑激活。

饱和完成要求：作用域中所有当前合法工作、未合并 effect、等价修复和应处理边界发现均为空，
且本次迭代没有源语义上的变更。缓存、marker bookkeeping 和内部维护不延长 saturation。
若有未支持或未处理的连接，只能报告 `quiescent-for-covered-program`／unfinished，不能报告完整饱和。

## 6. 没有全局事实表时怎样匹配

### 6.1 四个统一接口

```text
resolve(NodeRef, visible_cut) → typed constructor / parameter wiring
enumerate_members(EClassHandle, visible_cut) → 所有合法成员的惰性游标
enumerate_operator(op, constraints, visible_cut) → 精确位置／参数族游标
read_function(full_key, visible_cut) → Ready(value, version) | Pending | Missing(version)
```

内部位置来自配方，不局限于 Cell root 或最初的 coarse rule。
目录保存“模板的哪些位置能提供某 operator”和当前实例／参数域，不复制全部内部节点的完整字段。
指纹和摘要可筛选，但只能作候选过滤；没有假阴性的契约必须独立验证。

### 6.2 已知与未知连接

- 已知内部配方：直接读取固定槽位，不做结构搜索。
- 已知边界转移：取得相关端口后检查剩余 alias／guard，启动后继。
- 多个 Cell 提供 LHS：按共同参数和相等关系连接完整关联行；保留多值分支。
- 未覆盖连接：用上述游标执行通用虚拟图 matcher，报告其搜索成本；得到真实 binding 后
  可以建立新入口，但观察本身不自动证明所有未来 binding。

该 matcher 是残余执行器，不维持一套持续同步的旧全局事实表。
它可能仍然很慢；不能靠忽略残余路径获得表面加速。
可选择的有限覆盖实验模式必须明确输出其未完成范围。
单条规则能够成为模板，不等于它在全局中的所有合法 binding 已被发现。

### 6.3 相关性与不漏通知

同一 root 下有多个 `body`、候选或别名分解时，保留 `(root, body, …)` 的相关行。
不能把 body₁ 的 `inv(x)` 与 body₂ 的 `inv(y)` 合成一次匹配。
可在证实条件独立时保留因子化乘积，但枚举真实输出的成本不能消失。

订阅采用“读取版本 → 安装订阅 → 再检查版本”的握手，防止安装之间的更新被漏掉。
缺失键也能被订阅。键参数发生 union 后，迁移／合并订阅，并检查新建立的等价连接。
同一模板的订阅路由描述共享，每个实例只保存实际依赖；不复制全部消费者列表。

## 7. 构造、hashcons、函数 merge 和 union

### 7.1 局部构造和按需身份

执行 `Construct(op,args)` 先生成局部构造引用，类型、实际参数和来源位置明确。
后继配方可直接使用该引用。
以下场合需要解析／统一其身份：跨 Cell 比较、union、外部函数键、残余查询要求具体成员、输出。

构造键是 `(sort, operator, canonical arguments at cut)`，哈希仅加速，冲突必须精确比较。
父构造的参数尚未解析时，保留依赖 DAG；不能直接用不同 LocalRef 判定不同构造。
按依赖层批量归一化，或让 congruence 工作队列推进需要的层，不逐构造等待全局表插入。

某个隐藏节点的身份并非“永远不需要处理”。一旦任何当前合法消费者需要它，必须通过游标和
身份服务纳入计算。没有完备的需求目录时，不能声称整体匹配完整。

### 7.2 effect 请求格式

```text
EffectRequest
  EffectId / source rule / action position
  StageToken 与证据引用
  操作：Construct / Set / Union / Hide / Delete / Error
  typed local/global operands
  前置依赖与完整键
  稳定逻辑顺序键
  reply port
```

独立请求先并行生成；公共配方和固定字段不在每条请求重复复制。
内部纯构造可仅设置虚拟事实的激活状态。请求一旦合法公开，就必须能恢复完整 effect，
不能只留下“最终最优值”。

### 7.3 函数更新必须保留 actual reply

每个完整函数键有一个共享结果端口及版本序列；不同 Stage 的读是不同 read cut。
`Set` 返回 UpdateId／reply port，后继读取 actual merged result，不能读取 proposed 充当回复。
历史派生使用已绑定的旧值；新阶段读取新值，不能追溯修改已经构造的节点参数。

| merge 类型 | 执行策略 |
|---|---|
| 已证明纯、结合且交换的 min/max 等 | 按 canonical key 分组归约；同时保留要求可观察的输入构造 |
| old/new 等选择 | 按目标执行语义的稳定逻辑顺序处理，不能按线程到达顺序 |
| 构造型 merge，如 `Smaller(old,new)` | 保存有序构造配方链及全部候选证据，局部引用接续 |
| 非幂等 merge，如 `old+new` | 同值请求也不能省略；按动作身份去重重试，保留不同逻辑更新 |
| 要求相等／拒绝冲突的函数 | 只有规定的相等检查通过才接受重复写，否则保留相应错误；不自动 union 不同结果 |
| 读取其他键／产生 union／复杂回调 | 编译完整依赖及附带 effect；未知依赖进入显式慢路径或拒绝目标支持 |

constructor 的 set 按其源身份／等价语义单独降低，不能按普通可覆盖数值函数处理。
任何归约代数性质都要对具体类型和 primitive 成立，不能默认浮点 NaN 或有错误的运算满足整数规律。

不同函数键不一定独立：回调可能读取／修改共同资源，union 也可能令两个键合并。
先按已证明的读写依赖划冲突组；组间并行，必要时组内保序。
出现新的别名冲突时重新归并受影响组。不能只以“不同 root”授权并发。

### 7.4 块合并协议

1. 验证当前激活及输入版本，剔除未获准的提案；每个丢弃／挂起都有明确原因。
2. 对当前需要具体身份的构造解析依赖、精确分组，保留未逃逸的虚拟结构。
3. 为新增身份做确定性批量分配，建立 LocalRef/NodeRef 到规范句柄的映射。
4. 按 canonical 完整键组织更新；按声明策略计算函数结果和附带构造／union 请求。
5. 应用本次获准公开的 union，产生精确的 alias 变化事件。
6. 修复受影响构造键、函数键、容器与边界连接；新冲突再次进入工作队列。
7. 达到当前发布边界所需的一致性后，填写 actual replies，并发布版本变化。
8. 通知后继端口；输出仍留在 Cell 存储中，不默认重建所有旧表。

这是一组可接续的工作阶段，不意味着每步都由 CPU 等待 GPU 回传。
回调产生新构造、再触发 union 的循环可能需要多轮；不能假定一次归约完成。

### 7.5 局部等价修复

保留 `EClassHandle → 引用它的构造参数、函数键、容器和边界订阅` 的反向依赖。
共享模板的使用位置一次编译；实例依赖只记录实际引用。
Union 只把受影响引用加入 dirty 队列，同一个合法修复轮中重复通知去重。
物理行搬迁不应产生语义版本变化。代表 ID 改变不等于新增事实；成员集合扩大与函数值变化分别处理。

旧的纯正向事实证据可在合法相等替换后继续成立；数值 guard、可见性、缺失读取及其他
非单调前提必须重新检查。新 alias 还可能开启新匹配，不能只维护旧命中。
一个 union 仍可能影响全图，反向依赖只缩小通常情况，不提供最坏情况的常数成本保证。

## 8. 一个完整例子

两个已绑定的局部候选向同一个 `ExtractedExpr(root)` 提交更新：

```text
Cell A: tA=TermBop(op,tx,ty); cA=1+cx+cy; pA=TCPair(tA,cA)
Cell B: tB=TermBop(op,ux,uy); cB=1+dx+dy; pB=TCPair(tB,cB)
旧函数结果：pOld
```

1. A、B 从 marker 取得相关参数，纯计算可并行；tA/tB/pA/pB 都先是局部构造引用。
2. 两个 Set 带合法阶段与稳定更新顺序进入同一键组。
3. 若键或实际参数已等价，统一相应身份；不能只因两个 `TermBop` 类型相同而合并。
4. 若原 merge 构造 Smaller，保存 `s1=Smaller(pOld,pA)`、`s2=Smaller(s1,pB)`。
5. 合法后继阶段执行比较规则。一个代价 eclass 含多个 TCPair 证据时全部保留；
   只有经过认证的存在性查询才可使用 min/max 摘要，不能默认只保留一个赢家。
6. 比较成立产生可检查的 Union 请求，修复受影响的函数／构造键。
7. 后继读取 `ExtractedExpr(root)` 的 actual reply 及版本。内部构造继续由配方保存。
8. 若此后 `cx` 改变，重新激活相关读端口生成新的合法候选；旧候选与 Smaller 不会因缓存失效自动消失。
9. 若查询或 extraction 需要 s1，它可以通过 NodeRef 访问，不要求先回放整条历史。

验收中必须包含：A/B 生成同一构造、两个原本不同 root 被 union、跨阶段旧／新函数值、
相同数值的两次非幂等更新、双方都可能胜出的多候选情况，以及未覆盖消费者读取中间 Smaller。

## 9. 其他执行细节

### 精确数值与矩阵

固定选择器、仿射算术和可证明范围的数值列可以用矩阵计算；离散身份保持整数，不当浮点值计算。
i64 溢出、除零、哨兵和 NaN/浮点行为按目标 primitive 契约处理。
只有证明范围与精度足够时才使用低精度 GEMM；其他列采用精确整数／明确浮点模式。
mask、比较、分组与构造可使用普通 GPU kernel，但应共享同一份上下文，避免复制并来回搬运。
模板选择／岭预测可提出调度或候选，不能代替 guard 和 union 依据；第一版不依赖学习模型。

### 多值、容器与递归

Set/Vec/Map 等值保留自己的值语义和元素身份。Eq 元素 union 后按源语义规范化容器，
去重、顺序和哈希规则不能混用。支持尚未实现的类型在加载时明确拒绝，不当作整数放行。
后续可以用不可变共享容器块加版本／别名依赖避免全量复制。

参数化递归配方保存 guard、参数更新和子 Cell 接线；例如区间内逐项生成 Get/union。
生成程序的短描述不免除实际观察这些项时的输出成本。
未证终止的族不能标为 saturated；运行中保留动态实例／待处理工作。
不加入静默的候选个数或重试次数上限；资源不足显式报告 unfinished/error。

### subsume、delete 与外部命令

可见性作用于具体事实／构造键，不是删除整个 eclass。
被隐藏结构仍可能需要供 extraction、历史证据或源语义规定的 lookup 使用；这些访问权限分别建模。
delete 后旧读取／缺失订阅需要更新；delete 不自动撤销此前证明的全部等价关系。
重复构造、重新插入和等价键合并时的可见性策略必须由源语义导出，不能自定一个 OR/AND。

push/pop、外部 I/O、opaque primitive、运行中增删声明等未实现能力在 artifact 中列明。
若日后增加兼容模式，必须显式标成 hybrid，不把隐藏的 native 执行算成纯 Cell 运行时。

### 生命周期、资源与失败

- 指令准备失败不能提前触发未来 Stage 的错误；只有合法激活后才产生源执行错误。
- 预检容量与算术条件，批次中的错误位置使用稳定逻辑顺序确定；不能把整个任意 RHS 默认为事务。
- 有原生可观察部分提交的操作，记录 effect prefix 和失败位置；严格兼容尚未支持时明确拒绝该区域，
  不声称回滚一整个批次等价于原错误行为。
- 帧、订阅、版本和 proof receipt 按实际引用回收；旧 read cut 有消费者时不能回收其数据。
- 新旧版本使用活跃读者 watermark／引用计数管理；只保留仍需恢复的内容，不积累全部原始 tracing。
- 发布重试识别 EffectId，分配与 reply 回填完成后才确认消费，避免中断重试重复非幂等更新。
- OOM、取消、队列未清空区分于固定点。不会为了继续运行静默丢弃活动 Cell。
- checkpoint 首先仅支持一致发布边界，保存模板摘要、实例块、身份映射、版本、订阅和控制位置；
  不保存原始设备指针。中途 checkpoint 以后再加入完整 pending-effect 日志。

## 10. Extraction、导出与检查器

Extractor 通过逻辑接口读取 eclass 成员和子引用，可沿配方 DAG 做 DP／现有提取算法。
必须支持共享子图与循环，不能假定所有 Cell 内部都是树。
原 cost 函数、效应／上下文限制、用户选择规则保持独立，不用分配 ID 充当语义排序键。
第一次可按需为 extractor 生成它需要的有限图，单列这项开销；最终逐步改成直接游标访问。

检查分成三个层次：

1. **产物校验**：规则、类型、配方接线、权限与环境摘要；新 artifact 只校验一次。
2. **运行时关键检查**：边界输入、精确 guard、版本、alias、实际 merge 回复及 effect 重试。
   即使关闭诊断模式，授权所必需的检查仍存在。
3. **诊断审计**：保留压缩推导凭据，独立执行或还原局部图核对；可切换完整／抽样审计。
   未开启审计不意味着允许模型直接输出 unchecked union。

较小的完整覆盖用例比较全部逻辑图；真实非合流 Pass 3 检查每个 effect 的合法性、目标后端逐轮
重放和 extraction 结果。未覆盖项不要求与原生终态完全相同，但必须量化遗漏／未完成范围。
避免把“小型查询验证器又执行了全部原 LHS”隐藏在检查模式之外；审计开销单列。

Stage sampler 增加 `CellGraphProvider`：按 StageToken 解码用户要求的局部，保留 RipenInput、
虚拟／已提升节点、端口版本及 union 依据。不得为了画一小片强制全图物化。

## 11. CPU / GPU 职责与并行细节

先在 CPU 实现新的无事实表语义执行器，再将同一 IR 降到 GPU。
旧 native staged 路径保留为对照，不在里面继续偷偷积累一套新状态。

CPU 保留 parsing/typechecking、编译、artifact 验证、外部控制与结果请求。
GPU 常驻模板、实例块、活动队列、identity/alias 状态、边界目录、函数端口及 effect 请求。
正常执行传输控制与必要增量，不传整表 JSON、全部 binding 或每轮全图快照。

批次按共享配方和就绪指令段划分，不能让一个线程负责一整份任意大小 Cell 的全部推理。
长递归或多候选产生分块 continuation；分块是完整工作的调度，不是截断候选。
按真实产出做 prefix sum 分配，块内使用相对引用；跨块依赖使用 reply/event 队列。

不同冲突组并行。跨 threadgroup 的依赖用 kernel/queue 边界或已支持的调度机制表达，
不实现“所有 block 原地自旋等其他 block 到齐”的危险全局屏障。
减少 CPU wait 不意味着允许未完成的跨组写入被读取；发布状态及队列采用明确的内存同步协议。

确定性来自逻辑顺序、稳定分组、可复现分配和明确数值模式，不来自固定线程数量的假设。
CSR／哈希／排序索引仍可能存在，但仅用于身份、实际边界和冲突管理，不强制复制所有内部事实列。

## 12. 代码结构与实施里程碑

以下路径是**拟新增位置**，不是已经存在的实现：

```text
eggfuse/ir/cell_runtime.py                共享运行时契约与独立校验入口
eggfuse/analyzer/cell_storage.py          从已有证据导出结构、入口、残余域
eggfuse/compiler/cell_runtime.py          编排新增 pass，使用已有 pipeline receipts
eggfuse/compiler/targets/cell_cpu.py      CPU 物理布局与程序
eggfuse/compiler/targets/metal/cell_runtime.py

engine/cell-runtime/                     新 Rust crate，CPU 语义核心与检查器
  src/program.rs / identity.rs / graph.rs
  src/ports.rs / schedule.rs / effects.rs / merge.rs
  src/executor.rs / extract.rs / audit.rs / checkpoint.rs

engine/metal/cell_runtime/               同一 IR 的 GPU lowering 所需执行组件
experiments/cell_runtime/                固定输入、可复现脚本和文本报告
```

先独立模块，稳定后只迁移通用能力；不大批重命名既有实验，不在本轮删除旧参照实现。
正式加载器必须按 artifact backend/schema 明确选择，不能因某个 env flag 静默退回旧路径。

| 阶段 | 必须交付 | 通过条件 |
|---|---|---|
| M0：语义与 IR | 上述对象、访问接口、能力清单、独立 verifier；将现有用例转为测试规范 | 篡改类型／接线／union／Stage 证据会被拒绝；不同来源产物不能混装 |
| M1：CPU 无表 Cell | 初始导入、共享配方、虚拟节点、同模板批执行、纯构造和精确 guard | 多个 Cell 连续产生后继，正常推理零原生事实表读写；可恢复全部逻辑节点 |
| M2：身份与合并 | 跨 Cell hashcons、局部引用回填、union 反向依赖、函数 reply、有序／归约 merge | 重复构造、同键写、键 union、回调构造链、多候选等反例通过 |
| M3：开放边界 | 事件入口、逐端口订阅、内部位置目录、通用虚拟图残余 matcher | 迟到输入、union 新接线、多 root／body 相关性、实例重叠不漏报或混拼 |
| M4：真实多阶段与源操作 | Run/Repeat/嵌套 Saturate、版本截面、可见性、hide/delete、错误前缀；补齐目标所需容器和 primitive | future union 不泄露；容器 alias 正确；有限 repeat 不越界；后继复用已知接线，不能再次全 LHS 搜索 |
| M5：完整出口 | 按需 extraction、局部 UI、导出、checkpoint、审计 | 同一逻辑图可恢复；checkpoint 后不重复 set；提取不丢中间候选或效应限制 |
| M6：GPU 常驻 | 同 IR、SoA 批次、固定计算、并行 effect／冲突组、设备工作队列 | CPU Cell reference 与 GPU 的受控用例一致；逐轮可复现；无常态整表往返 |
| M7：真实工作负载 | 三个小 Pass 3 的全调度；随后 Raytrace Pass 3 | 明确支持／覆盖范围，提取质量与规模对照，独立计量维护和残余搜索，才讨论净加速 |

M1 就必须证明“没回表”，不能拖到 M6 才发现它只是另一层缓存。
M2 通过前不宣称通用 merge 可并行；M3 通过前不宣称单规则 Cell 已覆盖全图；
M4 通过前不宣称完整 multi-stage；Raytrace 不作为每次小改的默认回归。
M0 从冻结 Pass 3 生成逐操作、逐类型、逐控制节点的需求表；M7 前全部需求必须已有执行实现或
明确的同后端虚拟图残余实现。不能跳过不支持的函数／容器，然后声称完整 Pass 3 已跑通。

“源操作受支持”与“每个匹配都有快速 Cell 配方”是两张不同清单。前者是运行完整程序的门槛，
后者决定优化覆盖；未认证的优化使用精确残余执行，不删除原程序的可执行含义。

## 13. 测试矩阵与成本归因

| 测试组 | 必备情况 |
|---|---|
| 身份 | 跨块相同构造、不同槽位同值、不同模板共享子图、alias 后相同构造、循环、槽位复用 ABA |
| 证据 | 错误 binding、假 hash 命中、非法跨 sort union、不同实例参数混拼、规则环境变化 |
| 函数 | 缺失输入、迟到回复、旧值保持、同键多 set、old/new/min/max、非幂等相同值更新 |
| merge | 回调构造中间节点、回调跨键读取、union 合并函数键、再次触发冲突的依赖链 |
| 调度 | 普通 Run 不递归消费新输出、repeat 0/1/5、嵌套 saturation、until、阶段之间显式命令 |
| 可见性 | future union、subsume 单个 enode、delete 后再插入、隐藏节点参与身份但不作可见证据 |
| 发现 | root／非 root、无消费者时的休眠、空端口后来有值、订阅安装竞争、多 Cell 边界完整关联 |
| 恢复 | 随机合法事件序列后的局部／全图解码、extraction、不同 batch 划分、发布边界重启 |
| 资源 | 大关联分支、递归生成、容量增长、取消／OOM 不冒充固定点、活跃旧版本不被回收 |

小用例以独立解释执行和源规则对照验证；并加入受约束随机事件序列及重命名／重布局测试，
避免实现和测试共同依赖同一套错误的配方生成器。

每份报告必须分别记录：

- 编译/Bake/加载成本，运行时间，extraction，诊断与导出成本。
- 逻辑 enode/eclass/函数键数量、实际实例／槽位／提升身份数量，压缩库大小。
- CPU RSS、GPU buffers、版本与订阅、未合并 effect、峰值内存；不只报告描述符字节数。
- 内部直接执行、边界已知转移、残余发现的 binding 与耗时；正常路径旧表读写次数。
- 一次上下文建立服务多少 Stage、内部接续多少次、多少必要 effect、真正公开多少逻辑变化。
- union 影响的依赖数、重查与重算数、无关失效数、冲突组大小及最长串行链。
- 候选访存深度／被排除位置分布；基础索引优化与 Cell 保证分别记 credit。
- GPU 队列活跃、occupancy、带宽、寄存器／spill、同步与 kernel 数；区分 profiler 重放与端到端时间。

同一产物身份匹配时复用历史控制结果，按已有 bench/profile skill 执行。
拆开测试：虚拟存储、直接接续、端口订阅、按需身份、冲突组并行、矩阵 lowering。
不能把减少输出、关闭验证或更换非合流选择的收益归给 Cell 压缩。

## 14. 决策与停止自欺的边界

确定采用：先 CPU 语义原型；统一精确 IR；按需虚拟节点；版本端口；局部引用；显式冲突程序；
原调度权限；目标后端可复现；单独报告残余覆盖。不把机器学习设为正确性或启动条件。

保留到实测后决定：编号位宽、实例批次尺寸、哪些中间槽位值得缓存、何种矩阵编码／布局、
是否引入求解器或学习算法选择 Cell 划分。它们不能改变上述不变量。

最危险的失败方式是：每个 Cell 有一份完整内部行，边界再同步一份全局表，查询失败后还重新跑原 matcher。
因此各里程碑都审计“哪些逻辑信息存了几份、哪些结构又搜索了一遍”。
如果实际边界需要暴露几乎全部内部结构，或者 alias 扩散使大部分依赖每轮重算，
就如实报告该工作负载无法从当前封装获益；不能继续用节点覆盖率替代计算复用收益。
