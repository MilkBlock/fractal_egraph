# Bake 定制的精确 TPR：配对阶段只计算向量

独立 CPU 数值原型。复用前两份实验的四条原始 math rewrite 和两个参数模板：

```text
T0 = p0*(p1+p2)              # 12 个完整候选 Spine
T1 = p0*(p1+p2)+p0*p3        # 56 个完整候选 Spine
```

目标是满足比前一版更强的条件：**每个 Cell 独立编码；更换配对对象时不重编码；配对
不查询 constructor、不整理新的 binding 键、不调用原来的 matcher。**

本版只处理因式提取规则在两个模板的 root / 非 root 触点间的交互，不是四条规则的
完整执行引擎，也不是任意 Spine 的叠合代数。新增大 Cell 的闭包与新编码尚未自动生成。

## 1. 完整 Cell 编码是什么

数学上定义一个带模板分块的向量：

```text
Z(T,b) = block_T[ χ_T ⊗ h(b0) ⊗ … ⊗ h(bp-1) ]
```

- χ_T 是该参数模板全部合法 Spine 候选的向量，其结构由共享因子 DAG 表示；
- h(a) 是固定 Hadamard 码本中的一行，取值为 ±1；
- 实例只保存模板块编号和数值向量核，没有另一份实际 binding 元组；
- 原输入可以从向量精确恢复，配合模板能重新构造全部候选；
- 不物化整个高阶张量，也不枚举 χ_T 的候选项。

这是整个向量的**因子化表示**。不是把 64 个输入数字直接做普通点积就解决全部匹配；
后续计算的是由它们生成的结构张量的精确内积。不同的对称 binding 可以是不同编码，
但得到相同的交互结果；未声称全局唯一 canonical Cell 向量。

本实验的输入域固定为 16 个原子，码本 H 满足 H Hᵀ = 16 I。每个实例 4×16 个数字，
T0 的第四个槽位填 0。8 个实例共 512 个数值，含 64 个 padding 0。码本自身 256 个数值。
初始化选择 28 个输入码字；这些准备成本不是配对免费完成的。

## 2. Bake 怎样减少编码空间

Bake 在真实 RipSat 闭包中提取所有可达 Mul(k,u) 触点，包括非 root。T0 有 3 个锚点、
6 条联合 binding 描述，T1 有 5 个锚点、10 条。然后把 k 编译为有限的结构配方。

这里 k 只可能是 Input、两个 Input 的 Add、或一个二项 Add 再与 Input 相加。
因此不需要通用构造器／任意深度的张量编码。

令 h_a 为 a 的输入向量：

```text
Φ(a)       = h_a
Φ(a+b)     = h_a⊗h_b + h_b⊗h_a
Φ((a+b)+c) = (h_a⊗h_b + h_b⊗h_a) ⊗ h_c
```

不同树形属于不同正交通道。对于孩子形状不同的 Add，在 Bake 中固定角色顺序，
所以外层交换不再复制；相同形状孩子的交换由两项叠加表示。

因此 `(a+b)+c` 与 `(a+c)+b` 不会因为叶子集合相同而误匹配。没有添加结合律。
此实现不靠浮点近似、随机投影或 softmax。

## 3. 为什么内积精确

设结构 s 的一个分量有 l 个叶子位置，允许的不同位置排列集合为 G_s：

```text
Φ_s(b) = Σ_{π∈G_s} ⊗_j h(b_{π(j)})
```

利用 h(a)·h(b)=16[a=b]：

```text
<Φ_s(a), Φ_s(b)>
  = 16^l × Σ_{π,σ∈G_s} Π_j [a_{π(j)} = b_{σ(j)}]
```

在本实验中每份 binding 内输入互异，这些轨道分量互不重复。于是同一结构语义的内积
为 `16^l |G_s|`，否则为 0。除以固定常数就得到精确的 0/1。

**输入互异是契约。** 若有重复输入，轨道归一化会改变，且参数 Cell 原闭包可能因 alias
启用新匹配；当前显式拒绝，不能只修改一个除数就声称支持动态 union。

## 4. 运行时如何不展开地计算

把实例的输入向量核堆起来，一次计算：

```text
G = Hports Hportsᵀ / 16
```

每对边界结构的内积，再按 Bake 得到的固定配方计算 `Σ Π G[...] / |G_s|`。
这利用张量积内积的可分解性，不生成原先的 `(child.root,k)` one-hot 键。

`score()` 只读取数值向量、模板类型和预编译接线。不读取实际 ID/名字，不解码向量，
不查询 constructor。矩阵门决定合法交互之后才解码，用于输出 binding 和 RHS。
结构选择／调度仍由 Python 循环实现，不是 GPU kernel 或编译好的 CUDA 数据流。

本例配对阶段：

| 工作 | 实际数量 |
| --- | ---: |
| Gram 矩阵调用 | 1 |
| Gram 标量乘加 | 16,384 |
| 后续收缩标量乘法 | 3,408 |
| 收缩求和项 | 3,024 |
| 构造器查询 | 0 |
| binding 键构造 | 0 |
| 完整 Spine 枚举 | 0 |

6 个共享投影配方、36 个配方对在 Bake 时编译，不依赖测试用的具体字母。
这不是“比上次少多少操作”的速度比较：实验实例数、触点数、计算方法都不同。

## 5. 全部交互与原生核对

8 个实例，两个模板各 4 份，合计 32 个 root/non-root 触点、64 个有向因子通道。
外部仍然必须提供 `Add(left_port,right_port)`。原生 probe 同时固定左右 Port，避免
把同一 e-class 的其他 Add 表示混入这次指定触点对的匹配。

| 触点组合 | 带触点对标识的完整 binding |
| --- | ---: |
| root / root | 38 |
| root / non-root | 71 |
| non-root / root | 71 |
| non-root / non-root | 282 |
| 合计 | 462 |

去掉触点标签、按原规则 `(root,k,u,v)` 去重后为 **110** 个不同 binding。
462 不是 462 次新的提交变化，也不是全局唯一匹配数；实例别名会产生重复位置标签。

验证包括：

1. 输入码本严格正交、完整实例编码往返；
2. 压缩收缩与显式结构张量内积逐项一致（显式展开仅用于验证，19,264 个数值）；
3. 462 条完整 binding 与 native egglog 相等；
4. 原始 rewrite 实际执行后，所有预测目标的等价检查通过；
5. 交换输入的等价例子、叶子相同但括号不同的负例；
6. 新的 g/h/i/j/k/m binding 使用冻结的库，不重新 Bake，仍与 native 一致；
7. 对配对内核禁用旧 matcher、constructor lookup、投影构造、坐标 key 规范化及解码，
   内核仍正常完成。完整实验也禁用了完整候选枚举 API。

## 6. 范围与剩余问题

- 16 元素输入域；不是把无限身份无损放入固定小维度。
- 只验证两个模板和因式提取的 Var/Add 边界域，其他接口构造器直接拒绝。
- 不支持动态 union 增量更新，外部等价变化不能继续使用旧编码。
- 不支持重复输入导致的闭包变化；没有证明一般规则族都有小秩。
- 输出接线与原规则目标已恢复，但自动生成并编码新 Cell 尚未接入。
- 没有 GPU 性能、RSS 或相对原生 egglog 的加速结论。

这次进展是：在一个明确的、非平凡且带内部触点的有限域内，真正用独立编码后的向量
完成了配对，而不再先匹配再编码。不能将它扩大解释为通用 egraph 向量推理已解决。

## 复现

```sh
python3 experiments/cell_spine/tensor_interaction/demo.py \
  --output out/spine-tensor-next

# 已编译当前 native runner / lhs_ast 时可以加 --skip-build。
python3 -m unittest \
  experiments.cell_spine.tensor_interaction.test_demo \
  experiments.cell_spine.shared_matching.test_demo \
  experiments.cell_spine.factorized_boundary.test_demo -v
```

输出目录必须不存在。默认离线构建；Python 使用标准库。
页面展示完整编码、Bake 配方、root 矩阵、非 root 交互及可选择的 binding/RHS。
`vectors.json` 是实际数值输入核；`bake/library.json` 是固定共享表示；
`interaction.json` 是数值结果和解码输出；`graft-check.egg` 是原生执行验证源码。

思想来源：Smolensky (1990) 的角色/内容张量绑定。此处的交换轨道、有限正交码本、
Bake 定制投影与验证程序是本实验构造，没有复制外部实现。
